# 构建、测试与发布

适用基线：2026-10-22，VERSION 0.12.12。返回 [文档导航](../README.md)。除另有说明，以下 PowerShell 命令均在仓库根目录执行。命令是供开发人员使用的操作说明，不表示本次文档整理已经执行了构建、刷板或实机测试。

## 1. 环境准备

| 开发内容 | 当前工程要求 | 核对位置 |
| --- | --- | --- |
| Windows 客户端 | Windows、.NET SDK 10.0.401，latestPatch 回退策略 | `SoundConvertClient/global.json` |
| UI／音频包 | Avalonia 12.1.1、NAudio 2.2.1、NuGet 锁文件 | `Directory.Packages.props`、各项目 lock 文件 |
| 固件 | Pico SDK 2.3.1、Arm GNU 15.2.Rel1、CMake、Ninja | `SoundConvertBoard/CMakeLists.txt`、`tools/Build-All.ps1` |
| TinyUSB | 固定提交 `2f675abdd182163d03d4b25b47ad03497da23b1a` 和项目诊断补丁 | `SoundConvertBoard/vendor/DEPENDENCIES.md` |
| C 宿主检查 | Visual Studio C++ 工具与 Windows SDK | `SoundConvertBoard/tests/Run-HostChecks.ps1` |
| UDP 广播发现／恢复 | 选定网卡具有 IPv4，配套板卡固件 | `Runtime/UdpDiscovery.cs` |

锁定版本用于复现当前工程，不是在建议使用互联网上的最新版本。更换依赖时单独评估补丁、API、格式和运行表现，更新相应锁文件。安卓环境另见 [待开发说明](06-安卓客户端待开发说明.md)。

## 2. 首次只构建 Windows 客户端

SDK 的 global.json 按命令工作目录向上查找。先进入客户端目录，才能让下面的构建使用项目锁定的 SDK；传入项目路径本身不会切换 SDK 查找目录。

```powershell
Push-Location .\SoundConvertClient
dotnet restore .\UsbAudioBridge.slnx --locked-mode
dotnet build .\UsbAudioBridge.slnx -c Release --no-restore
dotnet run --project .\Checks\UsbAudioBridge.Checks.csproj -c Release --no-build
Pop-Location
```

后文在仓库根目录执行的 dotnet 示例应使用相同的已安装 SDK；要求严格锁定时可先进入客户端目录，并将路径按该工作目录调整。

这些 Checks 是控制台执行的协议／音频／本机回环检查，不是连接开发板的完整验收。若回环 socket 因受限环境被拒绝，保留错误并在允许本机回环的正常环境复验，不把权限问题直接判断为协议错误。

构建后可从 `SoundConvertClient/App/bin/Release/net10.0-windows/` 运行 App。需要完整 Engine 子目录；Engine 必须由前台提供 owner Job 后启动，不能直接双击后台 EXE 做常规调试。

## 3. 固件与联合构建

现有开发机脚本使用 `%USERPROFILE%/.pico-sdk` 中固定版本的 CMake、Ninja 和工具链，并按工程配置使用 `D:/GithubClone/tinyusb`：

```powershell
.\tools\Build-All.ps1
```

它先检查／按需应用 TinyUSB 只读诊断补丁，再配置和构建固件、restore／build 客户端并运行基础 Checks。默认将实验 `UAB_USB_CONTROL_NOTIFY` 设为 OFF。该过程会修改需要应用补丁的外部 TinyUSB 工作副本，首次操作前核对路径和已有改动；脚本不自动烧写。

不同开发机应先配置对应工具链和依赖路径，再单独 CMake。以下要求工具已在 PATH，并已准备好固定 TinyUSB 与补丁：

```powershell
cmake -S .\SoundConvertBoard -B .\SoundConvertBoard\build -G Ninja -DPICO_TINYUSB_PATH=D:/GithubClone/tinyusb -DUAB_USB_CONTROL_NOTIFY=OFF
cmake --build .\SoundConvertBoard\build --parallel 8
```

正常输出为 `SoundConvertBoard/build/SoundConvertBoard.elf` 和 `.uf2`，不是仓库自带的已验收镜像。CMake 目标只编译列出的 vendor 源文件；依赖目录中的上游示例不属于本固件。

运行固件宿主检查：

```powershell
.\SoundConvertBoard\tests\Run-HostChecks.ps1
```

宿主检查使用生产 C 模块与 Pico／TinyUSB／网络替身，不能证明真实 USB IRQ、跨核时序、Flash 断电或 PHY 行为。旧 `check_usb_descriptors.py` 保留早期描述符假设，使用前必须核对其预期是否适用于当前多 profile／HID；当前描述符覆盖还应结合 `usb_descriptor_profiles_test.c`、`usb_production_profiles_test.c` 和实际 Host 导出结果。

## 4. 按改动选择检查

| 改动范围 | 主要入口 | 需要补充的证据 |
| --- | --- | --- |
| 协议、缓冲、编码、重采样 | `SoundConvertClient/Checks`、固件 `tests` | 字节向量、非法输入、代次、时限和前后算法指标 |
| 页面、状态、草稿、按钮 | `tools/UiFeatureChecks` | 实际截图、最小尺寸、滚动、DPI、忙状态、失败恢复 |
| 真实 IPC／操作票据／托盘 | `tools/EngineUiChecks`，配合 `tools/EngineFixture` | 实例验证、命令最终结果、隔离配置、重复点击 |
| 前后台退出 | `tools/EngineLifecycleChecks` | 隐藏后继续、真正退出停止、强制结束回收；分清真实进程与替身 |
| 自动连接、监视、运行策略 | `tools/RuntimePolicyChecks`、`tools/DefaultAudioChecks` | 原网卡／ID、默认设备切换、明确设备不跟随、失败路径 |
| 时钟与时间侧带 | `tools/ClockSyncChecks`、`ClockTransportChecks`、`OutputClockChecks` | 资格门控、过期、预算撤销、Legacy 回退和实板软件采点 |
| 麦克风和双向流 | `tools/DuplexAudioChecks`、`ProductionDuplexChecks`、`AndroidMicAcceptance` | 实际采集／USB 录音、独立停止、双向连续性与输入资源回收 |
| 固件烧写窗口 | `UiFeatureChecks` 中固件窗口模式、Core UF2 检查 | 内存替身故障、目标移除、真实 BOOTSEL 和启动验证分开 |
| 发布包／安装维护 | `tools/ReleaseSmokeChecks`、Inno 脚本 | 文件版本、完整目录、许可、升级／修复／卸载配置保留 |

这些工具有不同参数和默认行为。运行前阅读对应 README／Program.cs，尤其含 `--board-check`、`--hardware`、acceptance、网络改址、媒体键或测试音的模式。不要将所有工具无参数批量执行；有的会打开真实音频设备或改变板卡状态。

例如运行基础 UI 替身检查，可指定隔离输出目录：

```powershell
dotnet run --project .\tools\UiFeatureChecks\UiFeatureChecks.csproj -c Release -- .\artifacts\acceptance\docs-example-ui
```

该示例默认使用替身与隔离预览，不是实板检查。实际窗口与截图仍需查看；单纯创建窗口或检查属性不能证明布局可用。

## 5. 只读实板联调起点

先记录台架，再搜索。下面的 IP 仅为示例，必须改为现场值；CLI 的 `info`／`firmware` 为读取，不要与 `--acceptance`、`start`／`stop` 或测试音混淆。

```powershell
$boardAddress = '192.168.1.50'
$localAddress = '192.168.1.10'
dotnet run --project .\SoundConvertClient\App\SoundConvertClient.csproj -c Release -- discover --local $localAddress
dotnet run --project .\SoundConvertClient\App\SoundConvertClient.csproj -c Release -- firmware --host $boardAddress
dotnet run --project .\SoundConvertClient\App\SoundConvertClient.csproj -c Release -- info --host $boardAddress
```

若当前另有软件持有 owner，只读会话不会获得管理权限。真正开始音频／修改配置前核对目标 ID、MAC、固件版本和 USB Host，避免把其他设备或旧 IP 当作目标。

## 6. 固件更新与串口

普通用户采用 README 的手动 BOOTSEL／UF2 流程。开发人员需要 SWD 时，确认探针、供电、SWDIO／SWCLK／GND 和板型，再明确选择 ELF：

```powershell
.\tools\Flash-Board.ps1 -Elf .\SoundConvertBoard\build\SoundConvertBoard.elf
.\tools\Read-BoardSerial.ps1 -Seconds 10
.\tools\Get-BoardUsbDescriptors.ps1
```

这组是**会操作真实硬件**的命令。串口脚本的 COM8 是开发机默认值，实际端口以脚本参数和设备枚举为准；UART 为 115200、8N1。烧写只写镜像覆盖范围，保留末尾 8 KiB 配置区，不做整片擦除。

OpenOCD 的写入／校验成功说明写入范围与镜像一致；UF2 传输完成说明文件写入流程完成。二者均不能代替启动、配置保留、USB 枚举、实际格式、网络和声音验收。

## 7. 实板前后对比怎么记录

比较前固定：源码快照、前台与 Engine 实际 EXE／DLL 哈希、固件镜像与读回版本、USB Host／端口、输入输出设备、网卡与拓扑、驱动、系统音量、配置、实际格式、编码、FEC、缓冲和时钟模式。一次只改变待测因素。

至少保留：

- 启动预热与正式稳定窗口的分界、测试时长和异常时间点。
- 板端 USB 收包、队列丢弃、过期、发送提交／SENDOK、两核最大服务间隔。
- PC 有效／非法／旧包、乱序／永久缺口、FEC 修复、欠载、重缓冲、水位和漂移。
- 进程 CPU、内存、分配、GC、锁等待、实际输出缓冲与回调时限。
- Host 当前真实 USB 格式、输入采集与实际输出证据。
- 前后结果、失败窗口、回退结果和未测范围。

低延迟结论需要同步参考／物理输出测量，不能把不同缓冲的配置值相加当作实测。短时组合通过不能扩写成长期、所有网卡或所有 Host 通过；相邻差分大也可能是正常音乐瞬态，需与同测试信号基线比较。

修改后若连续性、音质、CPU、控制响应或实际体验更差，回退该改动或只保留无干扰的诊断，不能靠隐藏计数、放宽通过阈值或改变对照工况接受退化。

## 8. 发布 Windows 文件夹与安装包

发布前确认旧程序及 Engine 已退出，选择一个新的输出目录，防止已删除组件残留。以下目录是本次手工选择的示例，不存在时才能作为干净发布位置：

```powershell
dotnet publish .\SoundConvertClient\App\SoundConvertClient.csproj -c Release -r win-x64 --self-contained true -p:RestoreLockedMode=true -o .\artifacts\publish-review\win-x64
.\SoundConvertClient\InnoSetup\Build-Installer.ps1 -SkipPublish -PublishDirectory .\artifacts\publish-review\win-x64
```

也可由安装器脚本在新目录中同时发布 App 与 Engine：

```powershell
.\SoundConvertClient\InnoSetup\Build-Installer.ps1 -PublishDirectory .\artifacts\publish-installer-review\win-x64
```

安装器脚本默认读取根 VERSION，验证 App EXE／DLL、Engine EXE／DLL 四个文件版本，以及自包含运行库与第三方许可。输出安装包及 SHA256；默认输出到发布目录父目录。维护、修复、升级、防降级及可选配置卸载见 [安装包说明](../../SoundConvertClient/InnoSetup/README.md)。

`tools/Package-SoftwareRelease.ps1` 是含固件、文档与证据的额外归档脚本，要求匹配版本的 `software-delivery.json`。当前脚本仍引用搬移前的若干 `docs/xx-*.md` 和历史包装说明；使用前应先核对并修正源路径／说明，不能假定在当前文档目录结构下直接可用。本次文档任务没有修改该发布脚本。

若取得带 manifest 的归档包，可运行：

```powershell
.\tools\Verify-SoftwareRelease.ps1 -Root .\artifacts\releases\V0.12.11
```

该命令以实际存在的发布包为前提；验证文件长度和 SHA256，不验证功能。不要因为本页给出示例路径就认为该版本发布包已经生成。

## 9. 一次变更应留下的材料

交付说明应记录：问题与目标、改动文件、版本、修改前后行为、实际执行命令及结果、失败和修复、产物哈希、硬件已测／未测边界、回退方法。文档只改动时检查链接、代码路径、格式、示例和语义即可，不需要为此重刷固件或重复完整音频长测。

`docs/开发流程`、`ToDo`、`artifacts` 当前被忽略；本组 `docs/开发指南` 应作为可交付的入门资料维护。提交前检查新增指南是否纳入版本控制，并核对所有正式入口不依赖只存在于本机的文件。
