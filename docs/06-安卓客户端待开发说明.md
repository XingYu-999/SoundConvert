# 安卓客户端待开发说明

适用基线：2026-10-22。返回 [文档导航](../README.md)。`SoundConvertClientAndroid/` 是**待开发的安卓客户端工程**。目录中存在 Gradle／app 结构，不表示网络音频客户端已完成、能够替代 Windows 版或已经通过安卓实机验收。

## 1. 先区分两种安卓角色

| 角色 | 与开发板的连接 | 当前状态 |
| --- | --- | --- |
| 安卓手机作为 USB Host／音源 | USB 连接开发板，使用系统 UAC1 声卡 | 属于当前 USB 桥接场景，具体机型与播放器兼容性需单独验证 |
| 安卓手机作为网络客户端 | 经 Wi-Fi／以太网连接板卡，手机负责播放／采集和控制 | 本目录的未来开发方向，目前待开发 |

新安卓客户端不等于已经删除的歌曲元数据配套 APK。它应围绕网络音频、设备控制与配置，不恢复通知读取、歌曲／封面获取、配对或 Host 绝对音量服务。

## 2. 可以复用的内容

协议契约、测试向量和算法思想可复用；Windows 编译产物和平台 API 不能直接照搬。

| 可复用契约 | 安卓侧应实现的内容 |
| --- | --- |
| UABD 发现 | 指定网络接口、广播收发、稳定设备 ID 与发现路径 |
| UABC 控制 | 完整帧读写、大端、严格 JSON、HELLO、owner、序号与 boot 校验 |
| UABA／UABF | 端口协商、PROBE、格式／代次校验、重排和可选纠错 |
| UABM | 采集转换、独立会话、约 1 ms 封包、保活与单独停止 |
| 配置事务 | 草稿、revision、准备／应用／确认／回滚及失联恢复 |
| 格式与音量语义 | 保存格式集合与实际 Host 格式分开，HID／内部增益／本地增益分开 |
| 缓冲与时钟思想 | 源／输出时钟区分、有限缓冲、漂移补偿、统计口径和前后比较 |

参考 [通信协议](02-通信协议.md) 及 Windows `Core` 实现建立独立测试向量；特别检查 uint64 十进制字符串、packed 24-bit 符号扩展、44.1 kHz 分数帧、代次回绕、ADPCM 自包含块和实际端口确认。

## 3. 必须独立设计的平台层

以下是后续开发事项，不是当前已实现功能或固定技术选型：

- 安卓播放／采集 API、设备路由、真实采样格式、缓冲与输出时钟读取。
- 麦克风权限、音频焦点、锁屏、后台执行、前台服务与通知的产品行为。
- 网络切换、Wi-Fi 与有线接口选择、广播限制及省电策略下的保活。
- 页面状态、配置持久化、生命周期取消和操作结果反馈。
- 安卓上的有界音频工作线程、缓冲池、过期处理和资源释放。

Windows 命名管道 IPC、Job Object、WASAPI 和注册表自启动不属于安卓协议要求。发现与未连接配置统一使用 UDP 广播；安卓实现需要适配网卡选择、广播收发、回复端口与平台网络权限。

“界面离开是否继续播放”和“明确退出是否停止所有资源”需要制定安卓产品规则并经过实机验证，不能把 Windows 进程实现机械复制过去。开始采集前必须有明确用户操作与必要权限。

## 4. 建议分阶段推进

| 阶段 | 具体工作 | 完成标准 |
| --- | --- | --- |
| A0 环境与边界 | 核对 Gradle／SDK、应用标识、依赖、权限、支持设备和运行方式 | 可构建最小应用，明确哪些功能待实现 |
| A1 只读控制 | 手动连接、HELLO、能力、状态与固件版本 | 与生产固件／TCP 替身互通，错误和 uint64 解析正确 |
| A2 发现与管理 | 选择网络、UDP 发现、稳定 ID、owner、取消及重连 | 错网卡、重复设备、断网和旧 IP 不误接管 |
| A3 单向播放 | PCM、自动端口、PROBE、有限缓冲与实际音频输出 | 先 48k/16，固定工况验证缺帧、欠载、调度与真实声音 |
| A4 可靠配置 | USB 草稿、事务、断连查询和回滚 | 未确认不显示保存成功，失败可恢复 |
| A5 反向麦克风 | 权限、显式采集、UABM 与独立停止 | Host 实际收到录音，退出和网络切换不遗留采集 |
| A6 扩展与发布 | 格式矩阵、HID、可选编码／纠错、长测与安装升级 | 分机型列结果，保留失败和未测范围 |

时间观测和实验时钟辅助应在基础连续性可复现后再评估。每阶段比较修改前后，实际更差则回退，不通过调大缓冲或隐藏缺帧计数宣称优化。

## 5. 与 Windows 客户端共存

开发板目前只有一个管理 owner 和两个 TCP 控制槽。安卓与 Windows 同时连接时，后连接可能只能只读；界面应明确提示，不能自动抢占现有音频。播放和录音会话须遵循已有 owner／端点绑定规则，不能假定支持多个独立播放接收端。
