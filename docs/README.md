# 开发文档导航

本目录为首次接触 USB 音频桥接工具的开发人员提供阅读入口。普通用户先阅读 [软件使用说明](../README.md)。

这组指南根据 `docs/开发流程` 中的设计、实施和验收文档整理，并核对当前源码；基线为 **2026-10-22，VERSION 0.12.12**。它描述当前实现和扩展方法，不把历史批次通过记录当作当前整机验收。

## 建议阅读顺序

| 顺序 | 文档 | 读完应能回答的问题 |
| --- | --- | --- |
| 1 | [软件架构](开发指南/01-软件架构.md) | 软件有哪些进程、线程、模块和数据流？在哪里找到业务入口？ |
| 2 | [通信协议](开发指南/02-通信协议.md) | 如何发现设备、建立控制会话、协商双向音频和保存配置？ |
| 3 | [Windows 客户端开发](开发指南/03-Windows客户端开发.md) | 一个界面操作如何经过 IPC 到达 Runtime 和开发板？增加字段要改哪些层？ |
| 4 | [开发板固件开发](开发指南/04-开发板固件开发.md) | USB、网络、双核队列、Flash 和灯效分别由谁负责？ |
| 5 | [构建测试与发布](开发指南/05-构建测试与发布.md) | 如何搭建环境、运行有针对性的检查、记录硬件证据并发布？ |
| 6 | [安卓客户端待开发说明](开发指南/06-安卓客户端待开发说明.md) | 安卓目录是什么状态？哪些协议可复用，哪些平台代码必须重写？ |

建议先完成“能构建、能读状态、能跟踪一次命令”，再改音频调度或 USB 描述符。一次只改一个可测量因素，并保留修改前后证据。

## 如何判断资料是否适用

- **用户当前操作**：以根 README 的页面与流程说明为入口。
- **现行实现**：以本组指南指向的源码、能力应答和实板实际状态核对。发现差异时更新对应指南，不能仅修改版本号。
- **设计和历史验收**：`开发流程` 保留早期方案及各版本结论，必须连同日期、版本、硬件、日志和未测范围理解。
- **规划**：`ToDo` 中的任务不等于已实现功能。安卓客户端明确为待开发。
- **验证证据**：`artifacts/acceptance` 中的编译、离线、回环、界面、烧写和实机报告分别说明各自范围，不相互替代。

现行网络采用免配对直接连接；播放使用 UABA，反向麦克风使用 UABM；音频端口支持按会话协商；IPC 为 v4；Flash 配置记录为 v8。歌曲信息、媒体配套服务、旧播放 `USB_SET_VOLUME` 及退出界面后保留独立后台的历史行为不适用于当前版本。
