## Avalonia 12 + .NET 10 的可行性

Avalonia 官方已发布 12 系列并采用 .NET 10。用户提供的本地 CommunicationTool 主项目当前使用 Avalonia `12.1.1`、`net10.0-windows`，说明这一组合已进入现有代码结构；不将声明了依赖等同于本次已构建验证。[Avalonia 12 官方说明](https://avaloniaui.net/blog/avalonia-12/)、[本地项目文件](/D:/Github/MyTools/CommunicationTool/CommunicationTool/CommunicationTool.csproj)

48k/16-bit/双声道仅 192 KB/s PCM，1000 个 1 ms UDP 包/秒。这一数据量本身不足以要求整体 C++。主要风险在分配、线程调度、缓冲与音频设备周期，而不是 C# 无法搬运这些数据。

| 方案 | 可行性与优点 | 成本/风险 | 推荐 |
| --- | --- | --- | --- |
| Avalonia + C# 网络与音频 | 结构统一，开发与调试快；便于复用现有配置/托盘模式 | 必须避免实时线程频繁 GC、阻塞锁及 UI 操作 | 首版 |
| Avalonia + C++ 音频 DLL | 原生 WASAPI、SIMD/ASRC 可集中优化；UI 保持 C# | ABI、生命周期、异常隔离、双工具链与发布负担 | 测量后局部引入 |
| 全 C++ 桌面应用 | 可统一原生资源管理 | 要重做 UI/MVVM/配置/托盘；不会消除系统音频缓冲 | 当前没有充分必要性 |
| 单独后台进程/服务 | 可隔离 UI 与音频故障 | IPC、部署、用户音频会话与安全边界更复杂 | 多客户端或稳定性需求明确后评估 |

Windows 音频输出与用户登录会话相关，首版是用户态托盘程序，不做 Session 0 Windows Service 播放器。Avalonia UI 可跨平台，WASAPI/Npcap/Startup 实现是 Windows 平台服务；未来 Linux/macOS 需要替换对应音频、二层网络和托盘后端。

## 音频后端

首版可用 NAudio 提供设备枚举和 WASAPI 封装，或建立自己的薄 COM 封装。选定版本后必须确认实际可控制的共享周期、事件驱动模式和缓冲行为；不能把 NAudio 构造参数中的 latency 数字直接当成实测延迟。[NAudio 官方项目](https://github.com/naudio/NAudio)

WASAPI 共享模式符合“与电脑自己的声音一起播放”。使用 `IAudioClient3` 查询目标格式对应的 default/fundamental/min/max engine period，选择设备支持的周期；遇到周期或格式被锁定时回退到实际可用值并显示。不是每台机器都能得到 1 ms 或 2 ms。[Microsoft 低延迟音频说明](https://learn.microsoft.com/en-us/windows-hardware/drivers/audio/low-latency-audio)

默认输出流程：

1. 通过稳定 endpoint ID 选择输出设备，记录系统 mix format 和支持的周期。
2. UDP 接收线程校验包头和 session，将有效 PCM 放入有限乱序窗口。
3. 按 sample_index 重建时间轴，丢包补零并短淡化，预填充约 4 ms。
4. 将输入 PCM 转为统一处理格式（建议内部 float），按声道映射与增益处理。
5. ASRC 将音源实际采样时钟对齐到输出设备时钟，同时处理 44.1k/48k 等名义采样率差异。
6. WASAPI 专用输出线程等待事件，按当前可写帧数供数；回调没有足够数据时补静音，不阻塞等待网络。

独占模式可作为高级测试项，但会影响同设备的其他声音，不作为默认。蓝牙耳机的编码/传输延迟独立于本项目，低延迟验收先使用有线耳机或音箱。

## 时钟漂移与 ASRC

即便两边都标注 48 kHz，USB 音源与 PC DAC 实际速率仍会不同。以 100 ppm 为例，48,000 × 100/1,000,000 = 4.8 帧/秒，约每 10 秒积累 1 ms 差异。4 ms 缓冲无法靠固定容量永久吸收这种漂移。

ASRC 设计要点：

- 输出设备时钟为播放消费基准；USB 音源时钟为输入基准。
- 从 sample_index、到达时间的长时间趋势和缓冲水位估计偏差；不能把瞬时网络抖动直接变成采样率抖动。
- 使用低通后的缓冲误差缓慢调节转换比率，限制变化率、积分和最大 ppm。初始可设 ±500 ppm，异常超限进入重同步并告警。
- 名义比率是 source_rate/output_rate，微小漂移校正在其附近；定义“输入帧/输出帧”的方向，避免控制符号相反。
- 稳态不依赖丢整包/重复整包校时；灾难性积压时允许显式重同步、清队列、淡入，并记录事件。
- ASRC 选择需评估插值质量、带宽、状态延续和尾部延迟。线性插值可用于早期验证，正式听音优先评估合适的多相 FIR 或成熟重采样库。
- 选择第三方库时锁定版本、许可与构建方式；不是所有“重采样器”都支持连续变比率。

麦克风回传以后单独实施：PC 麦克风采样时钟和 USB Host IN 消费时钟之间另建 ASRC，板端反馈消费计数与水位。不要用播放方向的比率补偿录音方向。

## 线程、队列与 GC

| 执行上下文 | 工作 | 更新频率 |
| --- | --- | --- |
| UI 线程 | 表单、导航、轻量图表、通知 | 电平建议 20–30 Hz；综合状态 1–2 Hz |
| 控制任务 | TCP、配置事务、认证、设备状态 | 按事件/定时；不占音频线程 |
| UDP 接收 | ReceiveFrom/ReceiveMessageFrom，校验，入队 | 约 500–1000 包/秒/流 |
| 音频线程 | 抖动缓冲消费、ASRC、WASAPI 写入 | 事件驱动，设备周期决定 |
| 低优先级后台 | 文件日志、录音、配置保存、历史加载 | 批量、有界 |

使用预分配缓冲、ArrayPool 或固定 ring，Socket/SocketAsyncEventArgs 或经过测量的 Memory-based 接口；不在每包创建新的 byte[]、LINQ 结果或 UI 集合条目。缓冲租借与归还必须遵守消费者生命周期，避免接收线程覆盖仍在播放的数据。

音频线程避免 async continuation 落到普通线程池。使用独立线程和适当 MMCSS 分类，所有 COM 初始化、释放、端点变更遵守线程规则。不要设置进程 `REALTIME_PRIORITY_CLASS`，它可能饿死系统关键线程。

采用有界队列；接收端按 sample_index 淘汰过期数据，不能在队列满后不断增长内存。C# 即使没有每包分配，也可能因全进程 GC 停顿受影响；用 ETW/EventPipe 测量，而不是依靠“低延迟 GC 模式”作保证。不长期用 NoGCRegion 掩盖分配问题。

### 何时加入 C++

只有满足以下证据之一才拆出原生音频核心：受控 CPU/GC 压力下欠载与托管暂停有明确关联；当前封装无法满足已验证的 WASAPI 周期需求；ASRC/DSP 成为主要 CPU 热点；有多流或复杂混音需求。

优先保留 C# UI/控制/发现，把 WASAPI 输出、ASRC 和必要的 UDP 接收集中到同一个原生数据路径，减少每毫秒 C#→C++ 往返。C ABI 只传固定布局标量、opaque handle 和明确生命周期的缓冲，不跨 ABI 抛异常或传 STL 类型。

接口可定义为“创建/配置/启动/停止/取统计/销毁”几个职责，统计用快照轮询，不能每个音频帧反调 UI。停止必须唤醒等待、join 线程并归还缓冲后再卸载 DLL。

### 设备页

提供搜索按钮、NIC 选择、手动 IP 添加、普通发现/二层恢复能力状态。列表显示别名、MAC、永久 ID 短码、有效 IP/掩码、DHCP/静态模式及实际网络状态、固件、USB 状态、是否已配对、当前管理者。

同一设备多路径合并为一行，展开后显示各 NIC。异网段发现结果标注“已发现，IP 控制暂不可达”，提供“设置地址”和“闪灯识别”。不要将发现成功渲染成音频已连通。

尚未获得租约的设备可经同二层路径显示“等待 DHCP，无有效 IP”，显示自动重试状态并提供“设置静态地址”；不能显示上一次地址为当前可用。搜索范围限定本地广播域，不提供跨路由器/VLAN 代理设置。

### 实时监听页

显示 USB 实际格式、输出设备、开始/停止、静音、增益、L/R 电平、目标与实际缓冲、输出周期、丢包、乱序、late drop、欠载、重同步和漂移。

首版默认用户点击开始；可以保存设备选择与自动重连偏好，自动开始播放单独开关，避免登录电脑就意外大声播放。输出设备被拔掉时默认停止并提示，可选跟随默认输出，切换需淡出/淡入。

显示“估计软件缓冲”与“实测端到端延迟”两个不同概念。尚未测量时显示“未测量”，不能把 4 ms jitter 配置显示成总延迟。

### 声卡配置页

首版直接显示 UAC1 固定模式。固件只支持 UAC1 时不显示无效 UAC2 切换。新增“开始模拟 / 停止模拟”按钮与模拟状态；名称、格式、声道等 USB 参数仅在设备确认 STOPPED 后允许编辑/提交，其他状态只读并提示先停止模拟。

USB 产品名与播放接口名的出厂默认值均为 `W5500-EVB-Pico2`。页面读取并展示设备当前配置，已有自定义名称不被默认值覆盖；网络设备别名和 PC 本地别名仍各自独立。

开发板上电加载已保存配置后自动开始 USB 声卡模拟，不依赖上位机认证；手动停止后重连不自动开始，显式开始或整机重启才恢复。USB Host 线无需拔出，“停止监听”不等于停止模拟。普通名称输入同时修改 product_name/playback_name，按协议进行准备、确认、保存；完成后仍停止，下次开始模拟或重新上电时枚举新参数。

STOPPING、FAULT、重连状态未知或配置事务占用时不开放参数编辑。UI 和固件均校验，导入/恢复出厂也受限；拒绝或失败保留旧有效配置及本地草稿，不悄悄排队重试。电脑本地监听音量/静音仍可即时调节，USB Host 的正常类请求照常处理。

### 网络配置页

默认自动获取/DHCP，与手动静态地址二选一。显示实际地址来源、租约剩余时间、网关、DNS、PHY link/speed/duplex。静态输入先验证网络/广播地址、前缀与网关；DHCP 当前租约是只读运行状态，不覆盖用户保存的静态设置。

删除自动备用地址的开关、说明和配置字段。DHCP 获取失败时显示等待/重试状态，可由用户主动切换静态；不自动改变模式。电脑直连且没有 DHCP 服务时提示使用同二层配置入口或预先配置静态 IP。

“应用并测试”进入带倒计时的临时配置；在新地址或二层路径找到同一 device_id，且候选模式已经有有效地址后提供确认保存。只找到二层设备但 DHCP 仍等待时，不显示“获取成功”。超时恢复旧模式，提示恢复后的实际地址或 DHCP 等待状态。改板 IP 不应连带修改 PC 网卡。

### 诊断与日志页

展示 USB reset/挂起、描述符档、最近错误、双核活跃、队列水位、SPI 超时、W5500 各 Socket 状态、DHCP 申请/续租/失效、静态地址冲突、输出设备周期、CPU/内存。网卡与系统资源详情默认折叠。

日志为有界缓存，可过滤设备、模块、级别和时间，导出前去除配对秘密。默认不记录音频内容；录音是单独显式功能，写盘队列满只丢录音数据，不阻塞监听。

### 设置页

分别设置登录自启、启动收起、最小化收起、关闭保留后台、自动重连、自动播放、输出回退、日志保留、配置导入导出和存储目录。提供恢复软件设置，不把它等同于清空板端网络/配对。

## 托盘与应用生命周期

| 操作 | 行为 |
| --- | --- |
| 关闭主窗口 | 默认隐藏到托盘，音频与网络继续 |
| 最小化 | 根据保存偏好决定隐藏；默认普通最小化 |
| 再次启动 | 唤醒现有实例，恢复窗口状态，不再建音频引擎 |
| 托盘单击 | 恢复主窗口 |
| 托盘菜单 | 打开、当前设备/状态、开始/停止、静音、设备、日志、设置、退出 |
| 托盘创建失败 | 不允许隐藏成无法找回的后台进程；改为最小化或关闭退出 |
| Explorer 重启 | 验证托盘图标恢复；失败时仍能通过二次启动打开窗口 |
| 系统锁屏 | 正常保持监听，设备策略可能另行挂起 |
| 睡眠/休眠 | 停止或冻结流，恢复后重新枚举 NIC/音频端点并创建新会话 |
| 真正退出 | 阻止重入、取消重连、停止流、释放音频、归还队列、刷日志、释放托盘 |

音频引擎由应用服务容器持有，页面离开或窗口隐藏不 Dispose。停止必须可取消和有超时，但协作取消期限不等于线程被强杀；超时记录具体组件并给出可恢复状态。

默认普通用户运行。自启使用本产品的当前用户 Startup 快捷方式或其他明确选定机制，UI 读取真实入口而不是只信 JSON。全用户安装产生的自启项要显示作用域，不能假装普通用户可直接移除。

首次启动显示窗口，即便保存了“自动播放”也应在完成配对、设备选择与输出确认后才启用。二次启动激活优先于“启动时收起”，参考现有 App 的行为。

## 配置与发布

本地建议使用 `%LOCALAPPDATA%\UsbAudioBridge\Settings`、`Logs`、`Diagnostics`。软件偏好、设备列表、音频输出、窗口状态分文件保存；板端配置以 device_id 关联，缓存标注 revision 和最后读取时间。

JSON 保存采用同目录临时文件、校验、原子替换；成功后再更新内存状态。损坏文件保留供诊断并提示，不用一套默认值覆盖所有用户配置。跨 schema 逐字段迁移，导入先预览差异。

发布先选 Windows x64 self-contained，测试没有预装 SDK 的干净机器。Npcap 为可选高级恢复依赖；只开放需要的程序/端口防火墙规则并说明网络配置文件。若引入 Native DLL，再增加 x64 ABI、VC++ Runtime 与 DLL 查找路径验证，不在没有原生依赖时无故加运行库安装负担。

## 首版边界

必须完成 UAC1 音源接收、W5500 硬件 TCP/UDP 网络监听、ASRC 稳定播放、DHCP/手动静态地址配置、本地发现和托盘。UAC2 切换、麦克风回传、系统虚拟录音端点、移动端上位机、多订阅、OTA 均是独立扩展，不能拖住第一条端到端链路。
