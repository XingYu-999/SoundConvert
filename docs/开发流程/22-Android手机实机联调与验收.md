## 本批修复

1. 小米输入法实测将邀请前缀改为 `uab－media：//`，使配对失败。邀请框改为 URI 输入、禁用建议并限制显示高度；新增 `uab-media://pair` 链接入口。链接只填入待确认表单并显示电脑地址、板卡与 USB 序列号，确认按钮才发起网络连接，不自动启动发送。
2. 统一验证邀请大小、IPv4、端口、证书摘要、一次性令牌、板卡标识及重复字段；配对期间防止重复提交，发送中更换接收电脑需先停止发送。
3. Android Binder 每次读取元数据会产生新的位图 generationId。原封面完成回调再次读取元数据、再次编码，形成反复处理。现仅在选择会话或元数据回调时缓存元数据并提交带修订号的封面任务；心跳与编码完成回调只发布快照，旧任务不能覆盖新修订。手机只读探针确认重复读取 generationId 确实变化，修复后接收端出现封面。
4. 返回应用刷新授权与会话；发送前核对当前有效选择。过期会话不能仅凭历史非空 ID 启动一个没有快照的发送连接。新进程或真实会话改变后仍需显式选择和绑定。

## 已有实测证据

原始记录在 `artifacts/acceptance/android-20261021-*`。正式版本窗口在 `artifacts/acceptance/android-20261021-final`；只保存必要计数、状态及内容哈希，不保存歌曲正文、用户音频、邀请、配对凭据、完整通知或私有配置。

- 配套 APK 已实际安装；通知访问与通知权限由用户手动授予。真实 TLS 配对成功，未绑定时电脑保持未知；显式选定来源／会话后显示歌曲信息。
- 标题哈希与手机原生 MediaController 一致；歌手、时长与进度可用。封面经过单独认证通道到达电脑，切歌后显示不同封面哈希。
- `final-pause.json` / `final-pause-frozen.json`：HID 暂停后为已暂停，两个采样进度相同；`final-resume.json`：再次 HID 恢复为播放中。
- `next-track.json` / `native-next.txt`：下一曲在电脑与手机原生会话标题哈希一致；`previous-track.json`：上一曲后的标题、时长与封面更新。
- 邀请解析的 9 项设备端检查通过。仪器探针会重启被测应用，因此不用于服务连续性验收；后续改用调试包中需 shell DUMP 权限的只读广播探针，不重启发送进程，发行 Release 变体不包含该入口。

连续播放、六键完整窗口、锁屏／断网恢复等后续结果以本目录生成的独立汇总为准；未生成通过记录的项目不记为通过。

## 失败与测量边界

- 保留安装被小米系统拒绝、输入法改写、旧进程会话失效及上一曲过渡时读取到原生停止状态的记录。曲目切换的回调存在先后顺序，验收应等待两端同一会话更新一致，而不是把瞬时读取当作最终播放器响应。
- 主动暂停导致 USB alt 0，恢复导致重新起播，其累计欠载／重同步计数与稳态播放分开。稳态检查比较同一 boot、同一接收器前后增量；不把累计非零重置为零，也不把稳定窗口推广为所有操作全过程零计数。
- 未测项目继续保留在根目录 `剩余工作内容.md`，Windows 睡眠／选择性挂起、其他 Host、模拟声学延迟和长期压力测试不由本手机窗口代替。
