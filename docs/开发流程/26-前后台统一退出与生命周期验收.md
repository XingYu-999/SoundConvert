# 前后台统一退出与生命周期验收

> 2026-10-22 当前规则更新：V0.11.3 起不允许退出软件后继续播放。托盘和设置统一退出应用，关闭到托盘仍保留进程；正常退出停流并结束后台，UI 被强制结束时回收所属后台。本文旧的退出后连续播放目标／结果保留作历史记录，不再作为当前验收要求，见[文档35](35-退出应用停止播放与后台回收验收.md)。

日期：2026-10-21。本批由当时根目录 VERSION 的 0.9.1 递增一次至 0.9.2。共享目录中的其他交付随后递增至 0.9.4，最终构建和本记录的正式验收采用 V0.9.4，不再为重试或修复递增版本。

## 当前行为

- 托盘只提供一个“退出”，设置页只提供“退出应用”。移除“退出界面（后台继续播放）”和第二套“停止后台并退出”命令。
- 正常退出先通知后台停止，再等待音频、麦克风、控制连接和后台进程清理。取消“关闭窗口时收起到托盘”后，窗口关闭也走同一条退出路径。
- 收起到托盘或隐藏窗口时 UI 进程仍然运行，保留原后台和设备会话。原单实例入口仍负责再次启动时显示窗口。
- UI 崩溃、被单独强制结束或直接结束进程时，由 Windows 回收其后台。后台不能在 UI 已退出后独立播放，也不能通过直接运行 Engine EXE 独立启动。

## 实现

保留 App / Runtime / Engine 的进程和音频线程隔离，由 `Runtime/EngineLifetime.cs` 管理 Windows Job Object。每个前台生命周期创建一个唯一的、不继承的 Job 句柄，启用 `JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE`。前台是该句柄的持有者，不增加另一个常驻系统服务。

前台启动 Engine 时传入 Job 名称。Engine 在创建 Runtime、开放 IPC 或初始化音频端点之前加入 Job，随即关闭自己临时打开的 Job 句柄。若前台在启动竞争期间已经退出，打开 Job 失败，Engine 以退出码 2 结束，不启动音频后台。前台退出时最后一个 Job 句柄关闭，Windows 终止其所属进程；机制依据 [Microsoft Job Objects 文档](https://learn.microsoft.com/en-us/windows/win32/procthread/job-objects)。

`EngineClient` 握手除版本校验外，还检查实际服务进程属于当前 Job，拒绝接管其他前台或旧版留下的后台。每次握手跟踪实际服务进程，避免单实例竞争时只等待已经退出的启动进程。

`DisposeAsync` 的并发调用等待同一清理任务。正常路径最多等待 3 秒取得 shutdown 应答，再等待最多 10 秒完成 Runtime 清理；IPC 无响应或清理超时会关闭 Job 回收后台，并等待进程结束。命名管道暂时断开本身不会误判为 UI 退出，原恢复逻辑仍可使用；退出请求后不重新启动后台。

## 交付与升级

运行 `artifacts/releases/V0.9.4-lifecycle/client-win-x64/SoundConvertClient.exe`，完整保留目录及 Engine 子目录。配套固件位于同级 `firmware`，文件与哈希记录见 `manifest.json`。

升级时先通过旧版“停止后台并退出”结束旧前台和旧后台，再启动新版本。新版不会强制结束不属于自己生命周期的旧后台；版本或归属不符时会提示退出旧程序。本次实现只改变 Windows 前后台生命周期，固件仅随根版本同步构建；同目录其他任务的固件业务变更归其各自验收记录。

未执行烧写、COM8 联调、USB 重新枚举、实板播放/麦克风或物理耳机验收。本记录的软件检查不替代这些硬件验收，也不把历史 UI 退出后继续播放的验收作为当前行为；文档16保留为 V0.4.0 历史记录。
