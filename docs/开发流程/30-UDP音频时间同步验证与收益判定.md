## 1. 判定问题与基本规则

验证分别回答四个问题：

1. 对表/样本时钟/输出时钟观测是否正确，误差是否足以支持下一步？
2. 增加观测本身是否干扰音频、控制、UI/Engine生命周期？
3. 相同缓冲和负载下，新控制是否提高连续性或时延稳定性？
4. 在同等连续性和声音质量下，能否降低实际端到端延迟？

任何一步答案未知，不能跳到后面宣布成功。模拟真值只验证模型；编译和回环不证明实板；Flash `Verified OK` 不证明固件运行、USB枚举或耳机无爆音。

`PASS / FAIL / NOT_RUN / BLOCKED / N_A` 分开记录。N_A仅用于明确不支持的硬件能力并附查询证据，不能把没时间测试归为N_A。超时、中断和工具故障保留已收集数据，不删除重跑覆盖。

## 3. 候选分组与公平对照（V01）

| 组别 | 内容 | 需要回答的问题 |
| --- | --- | --- |
| A0 | 冻结的原实现、原固件、原参数 | 修改前实际情况及既有失败 |
| B1 | 新代码所有新增功能关闭，匹配新固件 | 即使功能关闭是否已有回归 |
| B2 | 只启用时间报文/锚点，控制仍原样 | 额外网络/SPI/时间采点的影响 |
| B3 | B2＋软件对表拟合，只观测 | 拟合开销与估计有效性 |
| B4 | 三时钟完整ObserveOnly，仍用原PI | 输出时钟查询及全量观测的影响 |
| B5 | ClockAssistExperimental，原缓冲不变 | 控制算法本身的收益/退化 |
| B6 | 通过的B5＋更小缓冲目标 | 最低稳定延迟能否下降 |
| A-small | 原控制器采用与B6相同的小缓冲/其他设置 | 排除“只调小缓冲就能做到”的解释 |

B1–B6是实验标签，不是已发布版本。保留每组完整二进制；在同一批次版本号不重复递增，候选差异由哈希和candidate_id区分。

每次只比较相邻阶段；新固件和旧客户端、旧固件和新客户端先完成兼容矩阵。不把“旧客户端＋新固件”称为整套旧版本基线。修改固件的A/B每次重新烧写并读回版本/boot；会中断音频，测试窗口只能从重新就绪后开始。

短筛选采用配对/交错顺序，至少三对10分钟窗口，如A→B、B→A、A→B；优先按预先保存的种子随机化顺序。每次冷启动/重新协商条件一致，预热60秒，并单独保存预热阶段计数；对表未锁定的时间也记录，不从总结果抹去。

短筛选通过后做三对30分钟确认；至少两对2小时长测；拟启用默认的最终候选和基线各做8小时受控长测。长期环境漂移明显时增加交错重复，不把单次8小时结果当作统计显著性证明。沿用原验收更严格的门槛，不缩短已有必测时长。

空闲与压力作为不同场景；A运行时编译而B运行时空闲的窗口不可用于收益比较。记录所有无效窗口及无效原因，再按同一方法补跑。

## 4. 证据结构与计数口径（V02）

拟新增runner使用下列目录约定；创建时使用新run_id，目标已存在则拒绝覆盖：

```text
artifacts/acceptance/clock-sync/<batch>/<candidate>/<case>/<run_id>/
  manifest.json                  # 环境、分组、阈值、参数、seed
  hashes.json                    # 源码、产物、实际加载模块
  events.jsonl                   # 阶段、切换、故障与观测状态
  clock-exchanges.jsonl          # P1/B2/B3/P4、anchor、接受/拒绝原因
  audio-clock.jsonl              # 输出位置、frequency、配套QPC、HRESULT
  board-before.json / board-after.json
  pc-before.json / pc-after.json
  metrics.jsonl                  # 周期快照、窗口分位数和有效样本数
  failures.jsonl                 # 不只最后一个异常
  audio/                         # 测试素材/loopback/物理录音与校准
  result.json                    # PASS/FAIL/NOT_RUN等及逐门槛判定
  restore.json                   # 音量、设置、后台/设备恢复结果
```

日志写入独立有界队列；热路径不直接格式化JSON/写磁盘。队列满统计丢弃并保存原因；关键时间轴缺失则该次测量不可作通过证据。磁盘故障不能拖停音频，也不能静默继续报告完整数据。

使用首尾差值及分段增量；boot/epoch变化后另起分段，不对跨复位累计值做简单相减。回绕按字段位宽处理，区分正常回绕与复位。异常前后至少保留1秒高分辨率环形证据，连续性事件需能关联到对应音频序号/样本位置。

| 指标类别 | 必保留数据与解释 |
| --- | --- |
| 板卡播放供给 | usb_underruns、usb_resyncs、usb_expired_frames、usb_queue_drops、USB FIFO/phase wait、generation |
| 板卡发送 | audio_pending_expired、audio_send_timeouts/completions、poll/stream/core服务最大间隔；与时间包计数分开 |
| PC网络 | sequence缺口/乱序/重复、永久缺帧、late drops、接收间隔与批量、非法/旧会话包 |
| PC播放 | startup/steady underrun、rebuffer、overflow、resync、concealed/permanent gap、读耗时/锁等待/期限、prefill裁剪 |
| 时钟 | 所有原始时间戳/单位、拟合版本、斜率、残差、有效样本、拒绝原因、年龄、状态、前馈/PI/总ppm |
| 双向和控制 | microphone source_expired、capture missing/underrun、控制排队/端到端耗时/取消/unknown、keepalive间隔 |
| 资源 | CPU、内存、GC暂停/分配、线程/句柄、日志队列与丢弃、快照耗时、COM查询耗时 |

原始sequence缺口可能由乱序修复；永久缺帧、FEC修复、掩盖和原始丢包分别列出。`buffer_ms`以maxEnd估计时可能包含空洞，不自动等于可连续播放余量。计数全零不证明模拟输出声音质量。

现有AudioTiming统计只保留最近2048条，不能直接称为整个2h/8h的p99。新runner必须在各窗口收集可合并直方图/原始有界事件，给出样本数、采样策略和窗口；不同run的p99不能直接平均成总体p99。

## 8. 实板操作流程（V11）

每个case使用相同步骤，阶段切换立即落盘：

1. 确认目标板卡、测试PC、NIC、耳机端点和配置；备份音量/静音与用户设置。确认没有第二个测试工具占用owner/音频端口。
2. 如该组需要刷写，停止本轮音频/后台，保存旧镜像/配置后刷入匹配固件；记录写入日志。启动后通过串口/协议核对实际版本、boot、USB序列号和格式，不只看烧写成功。
3. 启动指定整套Engine/客户端，记录PID/实例/hash，选择指定耳机和输入端点；只在双向case启用真实麦克风。
4. 选择48k/16 PCM、FEC关闭、DSP关闭、默认3s监视和冻结缓冲档作为首轮；由板端实际格式及接收字节/帧比例确认，不凭Host设置界面推断。
5. 播放预生成的低幅度双声道测试信号，记录素材SHA；确认左右声道和未削波。预热60s，保存所有预热事件与锁定时间。
6. 取得board/PC阶段起点；开始10分钟正式窗口，运行预先规定负载；定期保存轻量指标，禁止高频全量JSON轮询干扰链路。
7. 出现欠载/音频块过期/爆音/超时即标记并保存前后事件。短筛选可按预定义规则停止；无论是否停止都生成失败结果，不从下一秒重新算“连续无故障”。
8. 正式窗口结束，保存末值、delta、录音、资源/时钟分布，记录退出/恢复结果；音量/静音恢复后再开始下一组。
9. 计算配对差异与门槛判定，核对运行参数没有漂移；不通过则停在该阶段并执行回退验证。

比较时从同一程序语义位置获取数据；新增代码只有B可见的时间戳用于诊断，A/B共同收益指标仍使用同一外部边界。观察连接采用已有owner或有界首尾查询，不增加常驻会话抢占板卡连接槽。

## 10. 故障注入与恢复验证（V18）

先软件受控注入，再真实短断/重启；注入器位于哪里必须记录，因为“解析后删包”不等于网络实际丢包。网络延迟注入需保存seed、请求/实际延迟以及注入前后时刻。

| 注入 | 实施/时长 | 正确行为 |
| --- | --- | --- |
| 丢时间回复 | 1个、连续3s、10s、30s | Acquiring/Holdover/Fallback符合定义，音频不因此重连/清空 |
| 时间回复延迟/重排/重复 | 20/100/300ms，固定序列 | 晚包拒绝、无旧模型回写、请求有界，无追补风暴 |
| 非对称延迟 | 单方向1/5ms，阶跃/渐变 | 记录模型偏差和置信限制；不承诺精确单向延迟 |
| 音频迟到/丢包 | 1/5/20/50ms批量；单包及连续2/5/20ms缺口 | 截止期限/掩盖保持语义，真实缺失保留，不将时间锁定视为可恢复数据 |
| USB供给变化 | Host暂停、alt0、格式切换、浅FIFO等待 | 代次/锚点失效；不能把供给间断解释为极大频差 |
| 网络中断 | 1s/6s，至少20次 | 原会话恢复机制正确，时钟独立重锁，旧token/boot包拒绝 |
| 板卡重启 | 正常重启和掉电重启各至少5次 | 新boot分段、无跨代次模型，不改配置布局 |
| 耳机失效/默认切换 | 每类至少20次 | 释放对应COM；新output_generation；失败则原策略明确恢复/停止 |
| 休眠唤醒/PC时钟显示调整 | 至少5次；系统墙钟调整在隔离验证环境进行 | 单调控制不跟随墙钟跳变；休眠后重建过期模型 |
| 日志磁盘不可写/队列满 | 工具模拟或独立测试目录 | 音频继续、日志缺失明确、测量不作PASS |
| 开关切换 | Legacy/ObserveOnly/Experimental各方向20次 | 总ppm和输出边界平滑，无新resync/隐式裁剪 |

超出缓冲的注入停顿允许按设计产生受控中断；它不算健康场景通过，也不能要求恢复不存在的数据。比较新旧恢复时长和波形，事件/丢帧增量应与注入原因一致，不能多出同步算法造成的失败。

## 11. 延迟与声音质量的独立验证（V19）

### 11.1 分层测量

- 软件阶段：同一PC QPC测量收包→Buffer.Add→Read；板端提取→PC收包需附mapping误差。UDP PROBE只测往返，不除以二冒充单向。
- WASAPI阶段：保存当前padding、实际buffer及音频位置关联；避免把已经包含的排队量重复相加。声卡时钟只是驱动报告的位置，不能单独证明耳机模拟延迟。
- 数字录音：WASAPI loopback可检查混音路径连续性/波形，独占模式另确认可用采集方式；没有录音不能填“音质通过”。
- 物理端到端：使用同一采集时钟同时记录源参考标记和耳机模拟电输出（或经校准声学耦合），通过相关/匹配定位。双通道采集路径需先做直通/通道交换校准，记录偏差、漂移、量化与重复测量误差。

若源设备没有可同步参考的模拟输出，可用与源样本建立关联的硬件GPIO标记＋示波/采集设备测“板卡提取→耳机”；必须标明它排除了上游Host/USB等待。不得把两台未同步电脑的录音文件起点差当作物理延迟。

物理设备不可用时，物理延迟结果标BLOCKED/NOT_RUN，只报告经过验证的软件分段收益，不能宣布完整端到端低延迟验收通过。

### 11.2 采样与质量

每个10分钟延迟窗口至少1000个可识别标记，间隔采用已知非周期序列或带唯一编号的脉冲/短扫频，避免重复音错配。记录应有/匹配/缺失标记数；缺失不能从统计中静默剔除。给出p50/p95/p99/max、误差预算及整窗覆盖率，不只有均值。

测试信号包括连续低幅度正弦、左右不同频率、静音↔有声边界、宽带/多音及可重复音乐片段。素材哈希、增益、DSP、录音路径与A/B严格一致。比较幅度、频率、残差谱、失真/噪声、掉音和瞬态；音乐固有大阶跃不直接判为爆音，必须与参考对齐。

健康场景至少20分钟耳机听音，随机隐藏A/B标签、等音量、相同片段，记录人员、顺序、异常时刻/声道和盲听意见。确认异常后关联波形/计数；没有听音不能写主观“无爆音”。物理录音、数字录音、主观听音分别得结论，不互相代替。

## 12. 预注册通过、退化与收益门槛

以下是本计划拟采用的初始工程门槛。V00结束、候选测量开始前冻结；如果测量能力或场景要求需要修改，另建实验版本、说明依据并重跑基线。不得根据候选失败结果事后放宽。

### 12.1 必须同时满足的绝对与非退化门槛

| 项目 | 健康、预算可满足场景的要求 |
| --- | --- |
| 板端连续性 | usb欠载/重同步/队列丢弃/过期、发送超时、看门狗复位增量0 |
| PC连续性 | 稳态欠载、永久缺帧、overflow、额外resync/rebuffer、read deadline miss增量0；首次初始化单列 |
| 音质与样本 | 无新增可复现click/pop/掉音，无隐式跳样/速率超界；合成/物理质量指标在冻结校准容差内 |
| 双向/控制 | 原P0失败独立闭环；source_expired/capture missing/underrun健康窗为0；500正常控制完成且无新增过期/unknown |
| 延迟非退化 | p50/p95/p99各自配对差的单侧95%上界≤εL；εL=max(1ms,2×测量不确定度U)，U及其含义须先校准 |
| 实时处理 | 新增读路径p99≤0.05ms；总Read/锁等待p99不超过基线max(10%,0.05ms)的增量容差，且无期限失守 |
| 资源/生命周期 | 满足开发计划预算；无持续内存/句柄/线程增长；UI退出不中断后台，关闭模式能停止新增活动 |
| 日志与范围 | 关键证据完整、无未解释缺失；所有目标必测项通过，未测不计通过 |

统计区间按run/连续时间块做配对重采样（建议至少10s块，方法及seed冻结），不能把同一串连续音频的每个样本当作独立重复。样本不足以判断时记“未证明”，不写“等效”。0故障长测只证明观察时段，不能承诺永不失败。

有故障的A0可以用于比较事件率，但不能以“B比A少”豁免B的绝对要求。若真实网络未能满足健康无丢包条件，标明网络负载/注入场景，单独验证恢复与纠错，不能改名为健康通过。

### 12.2 至少达成一项的实质收益

| 收益声明 | 必须具备的证据 |
| --- | --- |
| 降低延迟 | 相同连续性/音质下，物理p50与p95均降低至少ΔL=max(2ms,基线对应值的10%,2U)，配对95%区间支持改善，p99满足非退化；A-small不能达到相同收益 |
| 提高稳定性 | 在可复现相同负载下A有故障；B在全部确认窗/长测无对应故障，其他指标不过度退化；至少三对确认，低事件数时延长观测而非由1次→0次宣布成功 |
| 改善延迟波动 | A/B都无连续性故障，物理或明确定义的软件驻留p99−p50缩小≥20%且绝对缩小≥2U，平均/p50不显著变大，重复试验一致 |
| 仅诊断价值 | 对表提供可复核归因/阶段测量且开销通过；可保留ObserveOnly，但不能宣传为播放稳定性/延迟改进 |

缓冲下降本身不是收益证据，必须看实际驻留/输出/物理结果。平均延迟下降而p99变坏、稳定性提升仅靠缓冲变大、掩盖后故障计数减少，均不符合本计划的默认升级条件。

## 14. 回退验证与发布决策（V20）

1. 运行时实验模式失去资格后，在规定holdover内平滑退回Legacy；验证总ppm、样本位置、播放连续性和明确诊断事件。
2. 主动关闭功能，验证不再产生时间请求/额外输出时钟任务，UI/Engine重开仍按保存策略运行。配置损坏或旧版本配置默认Legacy。
3. 停止本轮进程，恢复匹配的整套A0 App/Runtime/Engine和固件；恢复配置快照、音量/静音。板卡配置区不整片擦除。
4. 核验运行hash/实际版本/端点/参数，重复原来暴露退化的相同case，再做至少10分钟原基线回放；若仍退化，不能宣称回退完成，需检查环境漂移/配置残留。
5. 保存旧/新版本交叉兼容结果，防止自动重连或旧Engine遗留造成看似降级实则仍运行候选。

最终决策只可为：

- **启用改进**：收益及全部非退化/绝对门槛满足，目标范围完整验收；更新默认与发布说明。
- **保留实验开关**：部分证据有价值但不足以默认启用；明确适用范围和未测项，保持Legacy默认。
- **仅保留观测**：诊断正确且开销可接受，播放收益未证明；不宣称低延迟升级。
- **回退/不合入**：实际更差、风险与维护成本超过收益，或关键测量无法支持结论。

交付报告必须包含失败和未测清单、所有候选对比、实际最低稳定档、物理测量范围、完整匹配回退包和恢复步骤。发布版本由根VERSION统一生成，一批次只递增一次；重跑/修复不重复加版本。
