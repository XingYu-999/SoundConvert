# Host 快捷控制闪烁修复验收

本批版本 **V0.12.3**，日期 2026-10-22。修复主页和播放页点击任意 Host 快捷按钮后，整个按钮区域短暂变灰及提示文字跳动的问题。

## 原因与修改

前台 `hostKeyInFlight` 和后台 `hostKeyPending` 原先同时参与六个按键的 `CanExecute`，发送开始时整排禁用，收到应答后再恢复。前后台还会把原提示临时替换为等待文案，造成短时间内的颜色和文字／布局变化。

按钮可用性现在只反映连接、管理权限、USB 模拟／枚举／挂起、HID 就绪和固件支持的按键。发送期间保留当前提示，成功或失败后更新结果。前台在发送入口忽略重叠点击；后台独立拒绝重叠请求，继续保留原有发送时效、设备状态复核和不自动重发规则，不缓存按键。

本批为客户端修复，固件仅根据根目录 VERSION 同步版本并重建。六个按键含义、独立声卡内部音量及实际 Host 响应确认规则保持原有语义。

## 验证记录

证据目录：`artifacts/acceptance/v0.12.3`。旧代码的定向检查保留在 `artifacts/acceptance/host-key-baseline`，失败点为点击后整排按钮不再可用，确认检查能复现本次问题。

定向检查使用原生 Avalonia 窗口、真实 MainViewModel、独立 Engine 进程及本机 TCP 设备替身。人为挂起设备按键应答，在此期间读取并应用后台快照、连续点击相同及不同按键，验证：

- 六个按钮始终保持可用外观；提示、按钮位置和所在面板高度不因发送开始而变化。
- 发送中连续点击不排队，一次操作只写入一个 HID 请求；直接绕过前台发送的重叠请求也被后台拒绝。
- 应答后文案匹配被点击按键，仍明确播放器状态未知。
- 覆盖主页 1200 宽度和播放页 1050 宽度；发送中截图供人工核对。

最终构建、现有界面回归、版本与文件校验结果见同目录 `software-delivery.json`。构建与原生窗口替身检查不作为实板结果。

| 检查 | 结果 |
| --- | --- |
| Release 构建／Windows 自包含发布 | 成功；生产构建无警告、无错误。 |
| Host 快捷控制定向原生窗口／IPC 检查 | 107 项通过，含前后台重复发送拦截和发送中快照。 |
| 现有完整界面回归 | 379 项通过，覆盖旧固件、只读、USB 未枚举／挂起、HID 未就绪等禁用边界。 |

| 发布文件 | 前台和 Engine 的 EXE／DLL 均为 0.12.3.0；实际 CLI、SHA256 和包内文件校验见交付记录。 |

现有界面检查工具仍有两处 `Bitmap.Save` 过时 API 警告；生产程序无对应警告。测试使用注入的假音频端点，截图中可能显示该端点的输出错误，不代表连接了实板或进行了真实音频播放。沙箱内 .NET 构建提前退出，使用本机 SDK 权限后完成，初始日志保留。

## 实板验收边界

本批未刷写、未复位开发板、未操作 COM8。需要用户在实际 USB Host 上复核六键响应及长按／连续点击体验；软件检查不证明真实播放器或音量已经响应。此界面修复使用完整新版前台与 Engine 即可生效，无需为消除闪烁而刷写开发板。
