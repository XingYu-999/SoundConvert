## 运行方式

运行发布目录 `client-win-x64/SoundConvertClient.exe`。首次打开时启动同目录下的 `Engine/SoundConvertEngine.exe`；已有同版本后台时接回当前状态。应完整保留 Engine 子目录。

前台只持有界面状态和命名管道连接；后台持有板卡会话、音频接收、WASAPI 播放、麦克风发送、保活、恢复及配置。后台运行库和后台程序均不引用 Avalonia。用户会话内单实例，命名管道仅允许当前用户访问；协议与发布版本须匹配。UI 与后台通过类型化状态、命令通信，PCM 不经过 UI/管道。

退出界面或结束 UI 进程后，后台继续当前播放与保活。再次打开界面接回原后台和连接，不重新建立音频流。设置、托盘新增“停止后台并退出”，用于显式停止音频、释放板卡会话并结束后台。关闭按钮是否收起到托盘仍由设置决定；两种关闭方式均不结束独立后台。登录启动项仍指向前台入口，由后台解析发布目录的前台位置。

当前后台是登录用户会话中的独立程序；本批没有安装 Session 0 Windows Service，也没有增加未登录播放功能。

## 音量与 USB 修复

1. 滑块及数值同步更新；设备写入在后台串行合并，仅保留最新待写值。已有请求继续收完响应，新的拖动值不取消正在进行的 TCP 请求。两端分别维护最新值与目标端点，端点切换使旧待写值失效。
2. 输出音量写入只写音量/静音，不再每次查询设备输出格式、WASAPI 混音格式与格式能力。全量设备信息仍按原低频策略刷新。
3. 拖动期间保护前台意图，快照只应用实际变化。远端 Q8.8 读回若表示同一个量化设置，保留原请求的滑块位置。后台不可达时撤销连接与操作可用状态。
4. 固件 USB_SET_VOLUME 为临时最新值控制，不占 32 条、60 秒的事务结果缓存；所有权、单调 request_id、boot 和 message_seq 检查保留。重复旧 request_id 仍拒绝；结果未知时读回状态，不盲目重放。配置等事务仍使用原缓存。
5. Android 窗口实测出现浅 FIFO：来包间隔正常、Core 0 服务正常时，CPU 的毫秒消费相位仍可能先于完整源块。现在保留 FIFO 中已有样本，最多等待 2 ms，完整块到达后重新对齐消费相位。样本序号连续，不复制、不补零、不裁剪；真正超时、溢出和不完整采样错误仍结束时间轴并计数。USB 块提取后的 4 ms 网络期限、FIFO 容量及 PC 缓冲上限没有扩大。新增 usb_fifo_phase_waits / usb_fifo_phase_wait_max_us 诊断。

## 实板候选与最终窗口

旧 V0.3.0 的 Android 连续音源 15 秒基线：缺帧、输出欠载为 0；此基线未持续拖动音量。协议取消的断连接路径另有本地生产代码复现。

第一轮 V0.4.0 音量实板候选保留在 `android-volume-second`：157 次板端音量变更没有缓存耗尽，主音量调节阶段无输出欠载；输出音量阶段出现板端欠载/重同步各 1，PC 输出欠载 2、溢出 1。约 42 ms 的网络到包间隔无序号缺口、对应 GC 停顿为 0。该轮不通过。板端相位等待修复后重新烧录，最终窗口另记，不覆盖失败证据。

相位修复后的 `android-volume-phase-final-3` 中板端故障计数增量均为0，但 Android 在窗口内改变 USB generation，PC 出现一次重缓冲；该窗口按音源中断保留为未通过。另保留两个初始化/无USB源超时窗口，不计为音频成功。最终结果以 `android-stable-window` 的原始计数和结果文件为准；通过范围限于实际 Android 24/48 音源、上述有线网卡与指定耳机。未验证本批 NS2、所有 Android 机型、96 kHz Android、模拟端到端延迟、两小时或 24 小时压力。
