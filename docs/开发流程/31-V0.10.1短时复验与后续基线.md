## 已修问题

1. 麦克风发送 worker 使用 Normal 优先级与 MMCSS，按绝对截止时间等待；新增有界服务间隔、唤醒迟到、源过期与 GC 关联诊断。
2. 断连清理当前设备身份；内部恢复保留独立目标身份。自动连接补齐手动断开取消、关闭开关、同 ID 歧义；IP 设置重新核对 NIC、列表代次、boot/revision。
3. 真实控制工具改为持久且验证身份的 IPC；失败也保存部分控制、分段计数和录音回调窗口。媒体键 200ms 期限、未知结果不重放及原延迟门槛保持。
4. 定位到后台 `RuntimeTimer → UpdatePlaybackMetrics → OutputDiagnostics → MMDevice.FriendlyName` 同步读取持续 524.18ms，完整覆盖失败键 524.01ms 的 dispatcher 等待；同期 GC、线程池、日志写入不解释该停顿。播放设备名现仅在构造时读取一次，定时快照使用缓存。
5. 保守缓冲档起播/明确重缓冲时最多保留 target 加一个实际输出 callback 所需的已到数据，仍受原 prefillCeiling/reserve/cap 限制。低于 40ms 的一包新鲜窗口保持，较大启动积压仍裁剪；活动时间线不跳样。独立整数前沿模型覆盖 80 个相位/停顿场景：已有 30ms 数据时 40 种 16/17ms 缺口相位连续；25ms 数据仍有 12 种超预算相位，不能保证任意首次停顿。该改动的实际水位/延迟需要如实保留，收益不归给后续对时。
