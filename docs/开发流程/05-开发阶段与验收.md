# 开发阶段、资源与验收

> 当前实现变更（2026-10-18）：0.4.0-dev 起已移除配对码、配对文件和 AUTH/HMAC 凭据流程。搜索选择设备即可直接连接；旧设计中的配对要求不再适用。设备所有权、序号、boot/revision、网络 challenge 与配置确认/回滚仍保留。以[当前协议](03-通信协议规范.md)及上位机/固件 README 为准。

以下是开发与验收清单，所有“通过”均需开发者实际采集证据；本次文档修订不包含板卡、USB 主机、网络或桌面运行测试结果。

## 分阶段实施

| 阶段 | 工作 | 退出条件 |
| --- | --- | --- |
| P0 工具与硬件 | Pico 2 Arm 工程、板型/Flash 检查、SWD、W5500 读寄存器 | LED/SWD 可用、版本寄存器稳定、PHY 链路正确 |
| P1 USB UAC1 | 按文档 08 的 U0–U4，将本地 clone 的 FS UAC1 路径接入现有 SoundConvert，48k/16/2ch OUT | 描述符/控制正确、反馈水位稳定、PCM 连续；无网络也稳定；reset/挂起/拔线恢复有记录 |
| P2 最短网络链路 | W5500 硬件 UDP PCM + PC 接收播放；可先手动静态 IP 测试 | 能听到连续声音，sample_index 与包序号正确 |
| P3 低延迟稳定性 | 小包、抖动缓冲、ASRC、队列上限、欠载诊断 | 长时间不因时钟漂移积压或耗尽；得到实际延迟分布 |
| P4 完整网络管理 | ioLibrary DHCP、手动静态、普通发现、同二层发现改址、鉴权回滚 | DHCP 续租/失效、无租约等待、静态改址和回滚通过 |
| P5 上位机产品功能 | Avalonia 页面、托盘、自启、单实例、输出切换、配置 | 窗口隐藏不影响播放，退出可恢复释放资源 |
| P6 目标主机兼容 | NS1、NS2、Android、USB-C/Lightning iPhone、PC | 发布明确的已测试设备/系统/连接模式列表 |
| P7 可选扩展 | UAC2、回传录音、原生音频核心、OTA | 按新增需求单独设门槛，不列入首版必须项 |

按用户后续确认：**可切换 UAC2 非必须，先按简单方案实施。** 第一版只要求 UAC1，不要求双描述符运行时切换，不因为上游支持两种类版本就把两种都纳入交付。

模拟策略按最新要求验收：上电加载配置后自动开始 USB 模拟，不依赖网络或认证；手动停止后重连不自动开始，显式 START 或整机重新上电才恢复。USB 名称和其他声卡参数只在停止完成后修改；保存后不自动开始。独立 USB 验收应在没有任何控制连接时先确认枚举，再验证网络不就绪时 USB 仍持续服务。

P2 到 P4 均使用 W5500 硬件 Socket 路线，不再更换为软件 TCP/IP 栈。网络模块可先按 [独立以太网文档](06-单片机以太网开发指南.md) 的 N0–N6 完成台架开发，再与 USB 集成；两侧接口通过有界 PCM 队列连接。

若 UAC1 在目标主机无法枚举，应先检查描述符、电源、端点同步、主机模式和线材。不要把“换 UAC2”当作通用修复；只有明确的兼容证据才扩大栈与档位。

USB 独立任务见 [USB 声卡开发指南](08-USB声卡开发指南.md)：U0–U4 对应 P0/P1，U5 对应 P2 集成，U6 对应 P3/P6。源码基线固定为 `2f675abdd182163d03d4b25b47ad03497da23b1a`，不是 `0.21.0` 标签；本次仅完成阅读与文档校对，不将任何任务标为实测通过。

P1 额外保留以下证据：

- 最小 UAC1 描述符：2 个接口、AS alt 0/1、仅 48k、OUT `0x01` 最大 196 B、反馈 `0x81` 为 3 B，无 HID/CDC。
- 名义消费 192 B/ms 与 USB 实际包长分开统计；检查实际读取长度、4 B 帧对齐、FIFO 覆盖及未知丢失时的时间轴重建。
- 反馈目标水位、FIFO 大小和消费 deadline 均有记录；网络停收不改变 USB 消费节奏。
- 验证 RX ISR 不阻塞；验证 reset 清理不只依赖 umount；外部供电下拔 USB 单独测试。
- 静音/音量实际改变 PCM；GET/SET、非法采样率/长度/channel/entity 的边界行为可重现。

## 声音正确性

- 发送固定频率、左右交替、脉冲和接近满幅的测试音，验证左右声道、符号、位深、容器对齐、削波、静音和音量控制。
- 48k/16/2ch 每秒名义 PCM 192,000 B；计数允许符合实际时基的微小差异，不能有逐包截断或多读。
- 44.1k 若开放，检查 44/45 帧分布、sample_index 连续性与一分钟总帧数。
- 对 UDP 人工丢包/重复/乱序，验证补零和淡化，不播放未初始化内存，不重复旧音频造成周期性回声。
- 使用录制的输入/输出作相关分析；音量、ASRC、混音可能改变样值，不把要求 bit-perfect 与需要变采样率的路径混在一起。
- 改名仅影响身份展示，不改变网络 device_id、MAC 或配对；重枚举后还能定位同一块板。
- 首次初始化与恢复出厂后，USB 产品名、播放接口名均为 `W5500-EVB-Pico2`；导出描述符核对字符串，并记录各主机的实际展示。自定义名称保存、重启和固件升级后保持，省略名称字段的配置更新不重置名称。

## 延迟目标与测量

建议先把“稳定听到声音”作为 P2 验收，再在有线 LAN、有线输出设备、正常系统负载下争取新增桥接延迟约 10–20 ms。若实际声卡最小周期较大，应报告实际达成值，不用修改统计定义掩盖。

| 环节 | 初始预算/假设 | 如何证实 |
| --- | --- | --- |
| USB FS 收包 | 1 ms 周期，具体等待随相位变化 | USB/SOF 计数、GPIO 标记或分析仪 |
| USB 异步反馈 FIFO | 文档 08 初始目标 384 B，约 2 ms | 实测水位与消费时基；必须计入桥接延迟，不能只计算 USB 周期 |
| UDP 聚合 | 1 ms 档约 0–1 ms 等待 | 板端时间标记与包边界；2 ms 档另记 |
| 板端/SPI/有线网络 | 争取 <1 ms，尚未测量 | 板侧 GPIO、受控网络与接收时间分析 |
| PC jitter target | 初始 4 ms，后续 2–20 ms 可调 | 实际 sample 水位分布 |
| ASRC | 与算法滤波器有关 | 明确算法群延迟和测试音相关结果 |
| WASAPI/驱动/设备 | 查询与实测，不能预设全为 1 ms | 实际 engine period、loopback/物理采集 |

这些环节部分会重叠，不能把每一项最坏值简单相加后称为实测；输入应用自身、游戏渲染和输出蓝牙等延迟单独报告。

测量方法：

1. PC 生成带清晰脉冲/伪随机序列的音频，通过 USB 送板，再经网络返回本 PC 输出；保留生成基准，记录输出设备设置。
2. 优先用同一采集设备的两个通道同步录下参考输出和桥接输出，通过互相关求差，校准两条模拟路径自身差异。
3. 若只有软件回环，报告为软件测量估计，说明生成、loopback 与硬件时基的偏差。跨设备未同步时间戳不能直接相减得到单向时延。
4. NS/手机测试不能直接沿用 PC 生成端的数字；可使用可重复声音内容和同步参考路径，保留平台差异。
5. 每轮报告样本量、P50/P95/P99/max、欠载次数、重同步次数、CPU/GC、设备与网络条件。不要只报最好一次。

## 网络功能验收

| 场景 | 必须观察到的结果 |
| --- | --- |
| 有 DHCP 开机 | 获得有效租约、地址来源 DHCP、普通发现可用 |
| 无 DHCP 开机直连 | 显示 DHCP_WAITING、无有效 IP，有限退避重试，不启动 IP 音频/控制 |
| 无 DHCP 时手动设静态 IP | 通过同二层鉴权配置，冲突检查和确认后业务可用 |
| 等待期间 DHCP 服务器上线 | 获取有效租约后开放业务，不要求重启或插拔 USB |
| DHCP 同地址续租 | 不无故打断音频 |
| DHCP NAK/租约到期 | 撤销失效租约和流，继续获取，不自动切换为已保存的静态值 |
| 同一交换机不同 IPv4 子网 | UDP 不可达时仍能通过 L2 找到正确 ID、认证改址 |
| PC 固定地址、板未获 DHCP | L2 找到等待状态的设备；认证改为静态后可达，未擅自改 PC 网卡 |
| 静态 IP 冲突 | 拒绝候选，仍可 L2 管理 |
| 改 IP/端口后不确认 | 到期恢复旧模式，能重新找到 |
| 改址过程中断电 | 启动使用上次已提交配置 |
| 多 NIC/VPN/虚拟网卡 | 只使用用户选中接口，正确展示来源，device_id 去重 |
| 防火墙阻挡 UDP | PROBE 失败被识别为路径问题，不显示正在正常播放 |
| 无 Npcap/驱动权限不足 | 正常 IP 功能仍可用，L2 功能明确降级 |

抓包中检查控制、声音、发现端口分离；TCP 大量读取状态/配置时 USB 和音频不因控制锁阻塞。S0 只处理二层管理/ARP 探测，未知 EtherType 被正确消费并丢弃；S1 音频仍使用硬件 UDP。

检查 TX/RX 分配分别合计不超过 16 KiB；8 KiB 控制 JSON 能跨芯片小缓冲分段收发；DHCP 内部冲突检查和发送等待不饿死音频。自动发现的发布验收限定本地广播域，不增加代理/中继开发项。

## 稳定性与故障注入

建议 P3 先连续 2 小时，发布前代表性平台至少 24 小时。环境与样本有限时如实说明，不能用一次短播放代替全部兼容性。

| 注入 | 观察点 |
| --- | --- |
| ±100/±300 ppm 人工速率偏差 | ASRC 水位收敛、无周期性整包跳音 |
| 0.1%/1% 丢包与有限乱序 | 质量下降可解释，无队列无限增长 |
| 20–100 ms 暂停与网络恢复 | 按策略静音/重同步，不补播大段旧音频 |
| 网线反复插拔、交换机重启 | USB 不中断或按定义恢复，网络状态可追踪 |
| USB 主机拔插、挂起、重启 | 新 epoch，旧包丢弃，环形队列状态重置 |
| 输出设备拔掉、默认设备变化 | 停止或按用户设置平滑切换，无崩溃 |
| CPU/磁盘/GC 压力 | 欠载与实际调度关联，有明确统计 |
| 打开日志、缩放 UI、切页面、收托盘 | 无明显影响实时数据路径 |
| 两个 PC 同时连接 | 单写入/流所有权规则生效 |
| 恶意长度、错误认证、重放旧会话 | 有界拒绝，无越界、无限内存或配置变化 |
| 配置写入各阶段掉电 | 至少保留一个有效配置副本 |
| 一核心停止推进 | 看门狗能识别并恢复，有复位原因 |

人为重现网络异常应在专用实验 LAN 或隔离环境进行，不对办公网络制造广播/ARP 风暴。

## UI 与托盘验收

- 关闭窗口到托盘，声音持续；托盘菜单状态和静音正确。
- 连续双击启动、启动即隐藏、已有最大化窗口恢复、不同权限实例分别测试；不能出现两个播放引擎。
- 托盘创建失败、Explorer 重启、系统注销/关机、睡眠恢复均能恢复可见操作入口。
- 自启开关反映真实 Startup 入口；保存失败回滚；应用不修改 CommunicationTool 的配置和启动项。
- 125%/150%/200% DPI、长中文名、窄窗口下内容不遮挡关键按钮；展开网卡详情不会让监听控制失去可用性。
- 配置导入预览差异；未支持 UAC2 时不显示可用开关；USB 名称/参数只在 STOPPED 解锁，提示下次开始模拟时生效。
- 真正退出后 UDP/TCP 端口、WASAPI、Npcap 句柄和原生线程全部释放，下一次启动正常。
- 配对秘密不出现在日志、诊断包或普通配置导出中。

## 模拟开关与配置验收

| 场景 | 必须满足的结果 |
| --- | --- |
| 上电 Host 线已插、没有上位机控制连接 | 使用已提交名称自动枚举声卡；USB 启动不等待网线、DHCP 或认证 |
| 仅发现、TCP 未认证、认证失败或只读观察 | 不触发模拟启动 |
| 本次 boot 首次有效认证管理连接 | 仅建立认证和所有权，不改变已运行或手动停止的 USB 状态 |
| RUNNING、Host alt0/挂起/物理拔线时改参 | 都不能绕过模拟状态写入限制 |
| 只停止监听/STREAM_STOP | 模拟仍 RUNNING，USB 参数仍锁定 |
| STOPPING 或停止清理超时 | 禁止改参；失败进入 FAULT，不假报 STOPPED |
| Host 线保留，停止完成后改名 | 保存成功仍 STOPPED，手动 START 后枚举新名 |
| 同时改格式、声道、Feature Unit 配置 | 与改名使用相同 STOPPED 校验和事务，不局部漏写 |
| 从导入、批量配置、恢复出厂入口改 USB 参数 | 同样校验模拟状态，拒绝时有效配置/Flash/revision 不变 |
| 配置事务与另一客户端 START 竞争 | 仅一个按序生效，事务持有时 START 返回 USB_CONFIG_BUSY |
| 手动 STOP 后刷新、控制重连、USB 插拔/resume | 不再次自动启动，也不自动提交草稿 |
| 保存后重启板 | 名称保留，加载已提交名称后自动开始，无控制连接也能读取正确 USB 名称 |
| 模拟运行时 Host 调整合法 UAC 音量、PC 调本地监听音量 | 正常工作，不误被网络配置锁阻止 |

## 首版发布门槛

必须有一条可重复的 UAC1→W5500 硬件 UDP→PC 共享播放链路；有长期时钟漂移处理；默认 DHCP、手动静态、无租约等待、同二层异网段改址均符合定义；配置可以恢复；托盘关闭不停止声音；公布实际测试过的主机和限制。

UAC2、C++、更高采样率、麦克风回传或 OTA 都不能替代上述稳定性。没有测量证据前，不承诺“全部主机兼容”“零延迟”“绝不爆音”或“网络 100M 所以任何格式都可用”。
