# V0.11.6 启动连接进度与取消／失败提示验收

日期：2026-10-22。本批次由 V0.11.5 递增一次至 V0.11.6。固件仅同步版本，连接协议、网卡绑定和设备身份约束保持。

## 显示规则

1. 前台等待音频 Engine 时显示“正在连接音频后台…”，与网络开发板连接分开。
2. 自动连接显示“正在自动连接 板卡名称…”，名称为空时使用已保存的设备唯一标识。底部状态栏与操作浮层同步显示目标；搜索当前地址时显示原网卡搜索阶段。读取板卡状态期间也保留自动连接目标，不提前复位为“未连接”。
3. 用户关闭自动连接或主动断开正在进行的自动连接时，显示“操作已取消：已取消自动连接 目标。”。该提示保留到下一次相关操作，而非只显示“未连接”。
4. 失败显示“连接失败（目标）：失败原因。需要检查的事项”。覆盖原网卡缺失／IPv4 变化、待确认网络事务、连接拒绝／不可达、超时、设备身份不匹配、协议异常、设备拒绝原因码及发现结果歧义。
5. 连接超时是失败，主动取消才显示取消。默认关闭自动连接或没有已保存目标时分别说明当前状态，不虚报用户取消。

例子：

```text
正在自动连接 W5500-EVB-Pico2…
连接失败（W5500-EVB-Pico2）：连接或读取开发板响应超时，且未发现匹配设备。请检查开发板供电、网线、所选网卡/IP 网段及防火墙是否允许 TCP 49161 和设备发现 UDP 49160。

操作已取消：已取消自动连接 W5500-EVB-Pico2。
```

底栏长文字继续使用省略显示和完整悬停提示，日志保留完整错误详情。托盘菜单的状态摘要限制长度，避免失败说明将原生菜单撑得过宽；完整说明在底栏／日志查看。

## 修复原因

原 `ControlSession.ConnectAsync` 的内部 5 秒期限使用取消令牌，超时直接抛出普通取消异常。自动连接流程因而可能把内部超时当成用户取消，不执行地址发现；界面又直接显示英文 `The operation was canceled.`。同时连接清理将状态设回“未连接”，初始化浮层使用默认“正在执行操作…”，首次失败原因也会在发现回退时丢失。

现在控制连接将内部期限转换为明确超时，外部用户令牌仍保留取消语义。自动连接回退只进行原有的一次发现及唯一候选连接，保留首个失败原因；不会切换其他网卡、跨网段冒连或放宽唯一标识校验。启动反馈按真实取消令牌区分取消与失败；退出软件的后台回收规则保持。
