## 1. 证据级别与结果格式

| 级别 | 能证明什么 | 不能代替什么 |
| --- | --- | --- |
| A 源码/静态检查 | 调用路径、状态来源、绑定/命令存在、版本一致 | 响应速度、硬件稳定性 |
| B 离线与替身 | 边界、状态机、协议错误、乱序/丢包算法 | Windows 调度、USB/W5500 性能 |
| C 原生 UI/真实进程 | 渲染/焦点、IPC、单实例、进程生命周期 | 实际音频连续、Host 响应 |
| D 实板/真实端点 | 指定 Host、板卡、网卡、耳机/麦克风链路 | 其他 Host/格式/驱动兼容性 |
| E 长稳/故障注入/听音 | 固定条件的连续性、恢复及明显爆音判断 | 任意机器和网络条件下的保证 |

每条记录固定字段：`case_id, source_manifest, release, engine_instance, host, board, format, endpoint_ids, nic, settings, load, duration, repetitions, before, after, delta, thresholds, result, evidence, limitations`。结果为“通过 / 失败 / 未测 / 不适用”，不适用写理由。不能以“仍出声”“程序没崩溃”作为通过依据。

## 2. T00 冻结基线

### 2.1 软件、配置与硬件

1. 保存根 VERSION、生产源码 SHA256、App/Runtime/Engine/固件 ELF/UF2 哈希、工具链、锁文件及构建参数。规划时的 [source-baseline.json](assets/ui-audio-plan-20261021/source-baseline.json) 只是源码清单，实施前重新生成，不能当作测试二进制证明。
2. 记录实际测试电脑：机器名、Windows 版本、CPU、电源状态、驱动、用户会话。截图中的 IP 不作为未来测试目标。
3. 冻结板卡 DeviceId/MAC/boot_id/固件、USB Host 类型/OS、USB 口和线、描述符与模式。当前串口约定 COM8、115200、8N1；先核对设备，不抢占已有串口程序。
4. 冻结 NIC ID/IPv4/掩码/路由、板 IP/端口、交换机或直连、协商速率、Npcap 状态。板播放 UDP 通常 49162、麦克风目的 49163、本机发送端口 49164，实际以协商结果为准。
5. 冻结耳机输出与麦克风 endpoint ID、采样格式、端点音量/静音、Host 音量、内部/本地增益、缓冲、FEC/编码/DSP。物理播放使用耳机；测试后在 finally 恢复改动的端点音量、静音及默认设置。
6. 备份 settings.json/devices.json 和未完成事务；替身测试使用 `UAB_UI_PREVIEW=1` 与独立 `UAB_PREVIEW_DATA`。只有明确实板场景才使用真实配置副本。

## 4. 生命周期

当前生命周期要求由 V0.11.3 的 `tools/EngineLifecycleChecks` 核验：正常退出和 UI 被杀后 Engine 必须结束。历史连续播放证据不能代替新契约。

| 用例 | 步骤 | 检查 |
| --- | --- | --- |
| LIFE01 | 正常退出／关闭窗口／托盘退出 → 重开 | 停止两向音频及后台，旧 PID 消失；重开按保存策略初始化新后台 |
| LIFE02 | 只结束 UI PID，不结束进程树，10 次 | 所属 Job 回收 Engine，不能残留声音输出或麦克风发送 |
| LIFE03 | 暂停 UI 消息处理 10s、IPC 客户端不读、导出长诊断 | 音频/保活持续，队列有界；恢复后用新快照，不回放旧媒体键 |
| LIFE04 | 两个 UI 同时启动、后台存在时再次启动 | 一个 Engine/管理会话；不重复创建音频流 |
| LIFE05 | 退出应用：IPC 正常／无响应／清理超时 | 先优雅停止；失败时仅回收本应用所属 Job，未验证的其他进程不强杀；退出后无所属 Engine |
| LIFE06 | 版本不匹配、Engine 崩溃、用户注销 | 不自动杀不兼容活跃后台；故障明确，恢复不重复键；注销验清理，不承诺继续音频 |

进程检查通过后，LIFE01–03 必须用生产 Engine+实板双向链路重做。替身不证明声音连续。显式正常停止可先用 3s 应答/10s 清理预算；超时采证并回收本应用所属后台，不强制结束未经验证的其他进程。

## 5. 控制延迟

### 5.1 分段时间点

每次操作分配 correlation/operation ID，并记录单调时钟：

- t0 UI 输入；t1 pending 实际渲染（渲染帧回调/原生采样，不仅 PropertyChanged）。
- t2 IPC 入队；t3 Engine 收到；t4 获得调度执行权；t5 TCP 真发送。
- t6 板端接受 ACK 到达；t7 UI 显示结果；t8 HID press/release 完成；t9 Host OS/播放器反应（可观测时）。

PC 同机进程记录可关联高精度单调时间和频率；板端微秒计数、boot 单列。未经校准不能相减 PC/板时钟。3s 轮询得到的 completed 计数只能给区间，不能作为毫秒级 HID 延迟；Host 用录屏/事件/可观测音量变化单独记录。

### 5.2 候选门槛

适用于健康有线网络、正式 Release、固定测试电脑。实施前冻结，失败后不能悄悄放宽。

| 指标 | 目标 | 样本 |
| --- | --- | --- |
| 点击→首帧 pending | p95 ≤50ms，p99 ≤100ms | ≥200 次 |
| Host 键点击→板接受 | p95 ≤150ms，p99 ≤300ms | ≥500 次，普通/双向压力分开 |
| ACK→UI 更新 | p95 ≤100ms，p99 ≤200ms | 不依赖下一次 3s 监视 |
| 已就绪端点输出启停 | p95 ≤500ms，p99 ≤1000ms | ≥50 次；冷启动/等 Host 单列 |
| 播放/输入保活间隔 | 压力下最大值 <2s | 板端失效期限 5s 前保留余量 |
| 托盘收起/恢复 | 无额外重同步/永久缺帧 | 和同长度对照窗口比较 |

>1s 必须有明确等待原因；超时不假报成功。冷端点初始化、USB 枚举、IP 事务不适用 500ms 完成目标，仍适用即时反馈。

| 用例 | 压力/故障 | 验收 |
| --- | --- | --- |
| CTL01 | 空闲/双向时启停、连接、媒体键 | 完整分段分位数，动作次数与接受次数一致 |
| CTL02 | 5 次/s 持续 60s；20 次/s 突发 2s | 正常满足目标；突发有界拒绝/过期可见，无晚到下一曲/积压/保活饥饿 |
| CTL03 | GET_STATS 人为延迟 500ms/3s | UI 立即反馈；不能抢占在途请求如实记录；未知键不重发，恢复正确 |
| CTL04 | ACK 丢失/断连/UI 重开/Engine 重启 | 不重放 USB_HOST_KEY；所有在途操作获得 Unknown/失败/取消等明确状态 |
| CTL05 | 输出未就绪/慢驱动/重复点击 | 一次操作只提交一次，最终按钮与实际状态一致 |

## 7. 音频稳定性与爆音

### 7.1 必采指标

### 7.3 故障注入与平滑质量

先离线可重复模型，再隔离链路实测。保存 seed/丢包序号，分别注入播放、输入，最后双向。

| 注入 | 验证目的 |
| --- | --- |
| 单个 1ms 包每秒缺一次 | FEC/短缺口补偿；有效电平计数不冒充原样本 |
| 连续缺 2/5/10/20/100ms | 找到可掩蔽→静音/重缓冲边界，不要求 100ms 断流不可感知 |
| 乱序 1–4 包、重复、冲突重叠、过期 FEC | 不回写已播放时间线，不重复计数/播放 |
| 0–5ms 到包抖动、周期 20ms burst | 水位/上限/节拍限制有效，不无限补发 |
| 断网 1s/6s、板重启、USB suspend/resume | 保活失效、新 boot/epoch、无旧键重放、平滑恢复 |

素材包含 -12dBFS 正弦、扫频、语音、音乐和静音进出；输入使用可复现信号及真实麦克风各一组。保存参考、输出和 Host 录音。Windows loopback 只能证明混音端，不单独证明真实耳机无驱动或模拟输出异常。

爆音判定交叉使用：

1. 固定信号的差分、二阶差、高频瞬态能量、削波和缺口边界波形，保留异常前后至少 100ms。已有 MaximumOutputStep/OutputStepsOverQuarterScale 是筛查，不是音乐绝对判据。
2. 对照音频先对齐增益、延迟与时钟漂移，再算残差；不能直接相减未对齐信号。
3. 相同耳机音量前后盲听；输入在 Host 实录后回听。记录人员/素材/时刻；确认明显 click/pop 即失败。“补偿帧非零”不自动失败，“无人报告”不自动通过。

轻微故障目标是无明显爆音、变化尽量不可察觉；长断流目标是淡出、静音和受控恢复，属于可听中断。基线后冻结每种素材客观筛查阈值并归档，不能因听不出而删除丢包数据。

### 7.4 资源预算

- 麦克风稳态不再每包分配：用分配计数实证，不能只搜索 new。
- AudioBuffer.Read p99 建议小于实际回调周期 50%，健康场景 read_deadline_misses=0；记录最大值和锁等待。板 task 预算按 USB 周期和现有期限检查。
- 遥测不能导致可重复音频退化；CPU/GC 三次前后对照，均值下降但 p99 延迟上升仍需处理。
- 长稳每分钟记录内存/句柄/线程/队列，最后 6h 不持续线性增长；覆盖日志轮换和 UI 收起时的快照预算，以及真正退出后的任务停止。
