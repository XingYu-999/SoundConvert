# 主页、虚拟声卡与播放改版（0.5.0-dev）

本次同时修改 Avalonia 上位机与板端固件。32-bit PCM 不在虚拟声卡支持范围内。

## 界面与操作

- **主页**：只显示虚拟 USB 声卡连接状态、实际 IP、UAC 协议、Host 当前格式与音量，以及电脑输出名称、播放状态、共享格式和端点音量。两组滑块独立。
- **虚拟声卡**：整合手动搜索、手动 IPv4 连接、历史设备、自动连接、USB 名称/格式/模拟、网卡配置与事务恢复。连接按钮未连接时为绿色，连接中显示“正在连接…”，成功后为红色“断开连接”。原 USB 声卡和网络导航已移除。
- **播放**：保留声音图标，选择输出、调整真实输出端点音量/静音，显示 WASAPI 共享格式和播放诊断。USB Host 音量入口位于主页和虚拟声卡页。本地监听增益仍在高级区域，默认 100%。

V0.0.2 按钮调整：连接／断开连接位于“手动搜索”左侧。模拟、监听分别合并为一个按钮，统一复用连接按钮的尺寸与绿色开始／红色停止样式；切换过程中显示进度并禁用重复操作。模拟以设备确认状态为准；监听以监听会话及恢复意图为准，等待 USB 音源、音源暂停或等待恢复时仍可停止监听。停止监听不停止 USB 模拟，停止模拟仍按原流程先停止监听。未连接和只读观察时不能开始模拟或监听，未决配置事务处理完成后才允许开始。

V0.0.6：Npcap 未安装或加载失败时，虚拟声卡页和“同二层恢复”中的二层搜索按钮均置灰；程序忙碌时也禁用。禁用后悬停仍可查看原因和安装 Npcap 后重启程序的提示。普通手动搜索与 IP 连接不依赖 Npcap。此检测复用进程内缓存的 Npcap 加载结果；网卡捕获权限在实际搜索时检查。

V0.0.9：搜索前在虚拟声卡页选择电脑网卡，下拉框显示名称、IPv4 与已连接/未连接状态，下面显示网卡说明；可刷新网卡。普通 UDP 搜索只绑定所选 IPv4，Npcap 二层搜索只打开对应网卡，即使电脑有多条到达同一设备的路径也不再同时扫描。本地接收 IPv4 为只读，管理 TCP 和音频 UDP 接收均绑定所选 IPv4。网卡没有 IPv4 时仍可使用支持的二层接口恢复设备，但普通搜索与连接不可用。连接期间固定网卡，切换需先断开；切换后清除原搜索结果。保存网卡 ID 与 IPv4，重启优先恢复同一网卡；网卡消失时不会自动换到另一张网卡。升级旧设置仅在旧接收 IPv4 属于本机现有网卡时恢复选择。

连接成功后可在“设置 → 自动连接”勾选“启动时自动连接已保存的虚拟声卡”。设置立即写入当前用户设置；默认不勾选，旧的历史记录不会自动变为自动连接目标，旧版本已显式启用的自动连接继续保留。断开后勾选状态仍反映实际保存的配置，也可取消。启动先尝试保存 IP 并校验 HELLO 的永久 ID；地址不在所选网卡网段或连接失败时，仅通过该网卡搜索一次，只连接相同永久 ID 且位于该网段的设备。网卡不可用、没有匹配项或再次连接失败后提示并停止该启动流程，不无限重试。手动连接、音频流原有的有界恢复仍保留。

## 保存声卡或网卡配置

运行时可编辑草稿。保存时，上位机停止本地流、发送 USB STOP，并轮询等待真正 STOPPED，再使用 VALIDATE → PREPARE → APPLY → CONFIRM 事务保存。保存成功后，如果原来正在模拟，重新过滤格式、开始模拟并恢复原监听意图；原来已经停止则保持停止。校验拒绝且尚未准备事务时尝试恢复原模拟状态。

网卡配置应用后，静态地址按新 IP 连接，DHCP 通过发现取得新地址，均校验原永久 ID。新地址和候选模式确认无误后才提交；CONFIRM 应答丢失时重连查询 COMMITTED，不重复提交已完成事务。静态重连窗口约 20 秒，DHCP 约 70 秒，每次 TCP 握手另受 5 秒超时约束。失败保留事务编号、设备身份和原模拟恢复意图；可在网卡配置区域查询、确认或回滚。设备仍按原协议的 30/120 秒确认窗口自动回滚未提交配置。

保存网卡不修改电脑 IP。跨网段后无法通过普通 IP 路径连接时，可使用已保留的 Npcap 二层恢复入口；二层恢复仍需显式确认和开始模拟。

## 16/24-bit 双声道格式

| 采样率（kHz） | 16-bit | packed 24-bit |
| --- | --- | --- |
| 44.1 | 支持 | 支持 |
| 48 | 支持 | 支持 |
| 88.2 | 支持 | 支持 |
| 96 | 支持 | 支持 |
| 176.4 | 支持 | 不提供 |
| 192 | 支持 | 不提供 |

板端保持 UAC1 / USB Full-Speed。上述格式的 OUT 包含反馈余量后最大 772 字节，未超过 Full-Speed 单帧 1023 字节限制。见 [Microsoft 的等时传输说明](https://learn.microsoft.com/en-us/windows-hardware/drivers/usbcon/transfer-data-to-isochronous-endpoints)。固件没有增加 UAC2。

用户勾选列表作为已提交偏好持久化，运行时再与当前输出可转换的输入列表取交集。V0.0.3 起，输入 PCM 经浮点解码和 ASRC 重采样后使用 WASAPI 共享模式播放；不再要求输出驱动能以独占模式原样接收源格式。源采样率不得高于设备输出和混音采样率，源位深不得高于这两个阶段的有效精度，且须保留双声道。允许升采样和位深扩展，不允许降采样或降低有效位深；分别检查两项，不以字节流量乘积代替。PCM 按 valid bits 判断；float32 的有效精度按 24 位处理。设备输出精度未知时不从混音容器猜测。

例如 24-bit/96 kHz 设备输出及 float32/96 kHz 混音允许 16/24-bit 的 44.1、48、88.2、96 kHz 输入，包括 16-bit/48 kHz → 24-bit/96 kHz；176.4/192 kHz 输入仍排除。24-bit/48 kHz → 16-bit/96 kHz 虽字节率增大，仍因降低位深而排除。升采样和扩展位深不会增加源音频已有的细节。输出面板继续分别显示设备输出和 WASAPI 混音格式。

开始模拟、建立管理连接、切换输出，以及每约 3 秒检测到输出能力或混音格式变化时，重新计算有效列表。若正在使用的高格式不再可用，停止模拟、收窄 USB 描述符后重新枚举，让 Host 在较低的允许格式中选择。模拟期间不支持的选项灰显，但保留勾选；停止后恢复可编辑。停止状态可保存当前输出不支持的偏好；开始模拟时若交集为空则保持停止并提示，不擅自启用用户未勾选的格式。

此过滤由已连接的管理上位机执行。板端独立上电仍按已保存偏好自运行；没有上位机时无法得知某台电脑的当前输出能力。Host 的实际选择仍以 GET_INFO 的 `format_selected`、alternate 与 `usb.format` 为准。

V0.0.5 起，alt 0 显示“当前空闲（alt 0） · 上次 Host 格式：24-bit / 96 kHz · 双声道”等历史提示。上位机只在观察到 `format_selected=true` 且实际格式有效时更新记录，按开发板永久 ID 写入历史设备文件，重新连接或重启上位机后可读回；不同设备即使复用同一 IP 也分别保存。没有历史时显示“当前空闲（alt 0） · 暂无上次 Host 格式记录”。空闲时协议 `usb.format` 中的默认参考值不会覆盖历史；该记录不代表当前正在传输。主页、虚拟声卡与播放页同步显示，较窄窗口自动换行。

## USB 音量与输出端点音量

同一台 Windows 作为 USB Host 时，仍按 USB serial 与 PnP 祖先准确匹配端点，通过 Windows 端点 API 发出真正 UAC 音量请求。

NS、手机等远端 Host 没有本机可操作端点时，可通过网络设置板端同一个 USB Feature Unit 主音量/静音。它影响实际转发的 PCM；设备不能强制同步远端 Host 的系统滑块，Host 后续写入会覆盖该值。界面显示真实 dB，并注明设备控制语义。没有另加第二层 USB 增益。

电脑输出音量直接读写所选 WASAPI 输出端点，覆盖该端点的系统音量/静音；不会把 ASRC 的本地增益伪装成声卡音量。约每 3 秒读回，也可在播放页刷新。

## 协议与持久化

- `usb.formats_mask`：uint32，非零且只能使用下表位。配置候选省略它时保留旧值；旧 `hi_res_enabled` 写法保留为 16/48 + 24/96 的兼容入口。
- 位 0–9 依次为：16/48、24/96、16/44.1、24/44.1、24/48、16/88.2、24/88.2、16/96、16/176.4、16/192。全选 `0x3ff`。
- `USB_SET_FORMATS`：管理权限、STOPPED、无待处理事务且 emulation revision 一致时，设置已提交偏好内的运行时子集。不会写 Flash。GET_INFO.usb.formats_mask 返回当前运行时列表。
- `USB_SET_VOLUME`：管理权限，参数 `master_volume_q8`（−15360～0）与 `master_mute`；Core 1 通过原子邮箱交给 Core 0 应用。`usb_control.source` 为 `device_management` 或 `usb_host`，Host 控制可覆盖网络设置。
- GET_CAPABILITIES 增加 `format_selection_supported`、`output_format_filter_supported`、`usb_master_control_supported`、`supported_formats`；GET_INFO.usb 增加 `protocol` 与 `formats_mask`。
- Flash v3 明确编码格式位图，继续双槽 CRC/独立提交页。读取 v1/v2 时保留名称、网络和 revision，并迁移原来的兼容/高规格选项；不整片擦除。
- 音频编码仍只有 S16LE=1、S24LE_PACKED=2。`packet_frames` 是一毫秒帧数的上界 `ceil(rate/1000)`；44.1/88.2/176.4 kHz 的实际包交替使用 floor/ceil，采样索引连续，每秒帧总数等于采样率。48 字节 UDP 头与 1200 字节上限保持不变。

新格式与远端 USB 音量需要同步更新 0.5.0-dev 固件；旧固件仍可连接及修改原有名称/网络，格式勾选会提示升级。

## 验证与交付（0.5.0-dev 历史）

本轮可运行程序为 `SoundConvertClient/artifacts/publish/ui-v0.5-win-x64/SoundConvertClient.exe`，需保留整个目录；配套固件为 `SoundConvertBoard/build/SoundConvertBoard.uf2`（SWD 使用同目录 ELF）。最终检查结果见本目录下的验收记录及仓库 `artifacts/ui-feature-checks-final`。新增原生界面/流程回归入口：

```powershell
dotnet run --project tools/UiFeatureChecks/UiFeatureChecks.csproj -c Release -- artifacts/ui-feature-checks-final
dotnet run --project tools/UiFeatureChecks/UiFeatureChecks.csproj -c Release -- --output-info
```

界面回归隔离设置目录，使用真实 TCP 协议设备替身与注入的模拟输出，验证七项导航、连接状态、只读权限、设备 ID、运行保存、改址重连、未知提交结果恢复、音量写入合并、格式降级和空交集。测试图明确包含“离线状态”，不能作为实板验收。`--output-info` 只读取实际 Windows 端点信息，不写音量、不播放。

固件宿主检查覆盖生产 USB owner、全部 1023 个非空格式子集过滤、配置 v1/v2 迁移和断电提交、所有采样率的一秒帧总数、音频包与生命周期；ELF 检查直接读取实际链接模板。Core 检查覆盖所有格式的解包、ASRC 双声道幅值及自动连接有界流程。

本轮未向实板烧写，也未执行真实 USB 重新枚举、多 Host 格式协商、网卡改址或长时间听音验收。构建、替身流程、模型和真实硬件结论分别记录。


V0.0.3 当前交付已完成固件烧写和 9 条真实音频通路验证，程序位于 `SoundConvertClient/artifacts/publish/win-x64`，独立归档位于 `artifacts/releases/V0.0.3`。详细结果和启动预热计数边界见文档 09 的 V0.0.3 章节。
