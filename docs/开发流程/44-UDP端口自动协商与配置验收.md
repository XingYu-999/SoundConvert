# UDP 端口自动协商与配置验收

日期：2026-10-22。本功能批次由 V0.11.11 递增一次次版本为 V0.12.0。同一工作区 USB 烧写窗口批次随后将根目录 VERSION 推进为 V0.12.1，本功能最终随统一 V0.12.1 构建交付，不回退或再次递增版本。

## 原实现与修改

原代码已具备 PREPARE 返回端口和 UDP PROBE 确认，但正式运行仍固定绑定软件播放 49162、麦克风 49164，固件固定使用播放 49162、麦克风 49163。它具备端口交换流程，未具备双方完整自动选端口功能。

现在删除“详细信息”折叠区，在“虚拟声卡”页声卡配置卡片之后增加常显“端口状态”。活动流显示描述符中的真实端口和方向；未启用时显示已保存的自动／固定策略，不用默认数值冒充实际协商结果。

设置页增加四个字段，按“声音输出／声音输入”与“虚拟声卡 UDP／本软件 UDP”排列。默认填写“自动协商”；也可填 1024–65535 的整数。软件按用户保存配置使用，四个字段随保存命令一次提交，完整验证后原子保存；未保存草稿不会被其他自动保存路径提交。真实 IPC 检查曾发现普通文本同步和保存命令的时序竞态，现已通过命令携带完整四项草稿解决，并验证失败请求返回失败票据、保留原配置。旧配置缺少此字段时自动采用四项自动策略。

同一端的两个固定端口不得相同，声卡端保留发现 49160 和控制 49161。手动端口被占用时明确失败；自动软件端通过操作系统绑定端口 0 后取得实际端口。每个 socket 独占绑定，防止误复用其他程序的音频端口。保存设置不打断当前传输，下次开始输出或启用麦克风时生效。

## 协议与固件

- `GET_CAPABILITIES.udp_port_negotiation_v1=true`、`port_configuration=true`：仅表示支持会话级音频 UDP 端口配置，不改变 TCP 49161、发现 UDP 49160、IP 配置事务和 Flash 格式。
- 两种 PREPARE 请求保留 `receive_port` 为软件已绑定的真实端口，增加可选 `source_port`：明确传 0 表示声卡端自动选择；1024–65535 表示指定声卡端口。缺失或 null 表示旧客户端兼容请求，继续使用播放 49162／麦克风 49163。
- 自动分配从 49152–65535 选择，跳过保留端口及其他已打开硬件 socket 的端口，最多尝试 32 次。指定端口无效、保留或冲突返回 `UDP_PORT_UNAVAILABLE`；硬件绑定失败返回 `UDP_BIND_FAILED`。
- PREPARE 成功返回实际 `source_port`。播放、麦克风探测、数据、socket 异常重开、状态 JSON 及可选时钟侧带均使用协商后的端口；时钟侧带继续复用播放 socket，不增加硬件 socket。
- 客户端检查固定端口是否得到确认；不会把固件忽略指定端口当作成功。旧固件忽略自动请求时兼容其固定返回端口，页面提示兼容状态。旧固件缺少能力时，非默认固定声卡端口在启动音频前拒绝，并提示更新固件。
- 新一轮麦克风 PREPARE 清除旧探测状态，仍必须使用本次身份和端口完成 PROBE 后才能 START。

完整声卡自动分配需要配套新固件。软件兼容旧固件时，本软件端仍可自动选端口，但声卡端保持旧端口。

## 验证与交付

固件与上位机 Release 构建通过。最终离线检查 1342 项通过，其中新增 24 项真实回环 TCP／UDP 检查覆盖两方向自动／手动协商、实际探测端点、独占绑定占用拒绝及固件忽略手动端口的失败处理。固件现有主机检查通过，新增 14 项端口分配模型检查涵盖边界、保留、冲突、回绕和有界尝试。它们均不等同于 W5500 硬件验收。

原生界面 353 项检查通过，覆盖默认值、四字段保存、冲突保护、旧配置读取、底部卡片顺序及截图。真实前后台 IPC 和替身后台回归 655 项检查通过，含端口保存完成／失败票据及恢复自动策略。界面截图已查看，四项字段及底部状态在最小窗口仍可读。
