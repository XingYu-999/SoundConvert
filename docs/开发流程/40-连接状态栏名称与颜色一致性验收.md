# V0.11.8 连接状态栏名称与颜色一致性

## 显示规则

- 连接流程结束后，底栏显示 `已连接 · 已连接的设备名`。名称取当前连接读取到的 USB 产品名，缺少名称时使用设备唯一标识。
- 普通连接、自动连接成功及周期状态刷新均使用该显示；设备名称变更读取成功后同步更新。
- 底栏橙色依据 `IsConnectionReady = IsConnected && !IsConnecting`。TCP/HELLO 已建立但身份、配置、能力及初始设备状态仍在读取时保持灰色；前台仍等待 IPC 完成确认时也保持灰色。流程完成后显示橙色和已连接名称。
- 错误提示继续优先显示。管理／只读角色仍在设备连接摘要中显示，USB RUNNING／STOPPED 仍在声卡模拟和设备监视中查看。

## 原因与实现

原底栏颜色直接绑定 `IsConnected`。后台在 TCP/HELLO 建立后就将该值置为真，此时连接方法还未完成；V0.11.7 前台等待后台终态和快照确认期间也会保留“正在连接”文字。不同阶段的信号因此产生橙色和连接中文字并存。

现在保留内部 TCP 会话状态供现有连接及恢复流程使用，新增只用于显示的完成状态。后台和前台各自按 `IsConnected` 与 `IsConnecting` 派生完成状态，并在两者变化时通知颜色绑定。连接完成和周期刷新使用相同的连接名称文案，避免底栏再次被“管理连接 · USB RUNNING”覆盖。

## 验证

证据目录 `artifacts/acceptance/v0.11.8`，最终数量及文件版本见 `software-delivery.json`。

- 原生界面检查在真实本地 TCP 替身已完成 HELLO 后，故意阻塞 GET_INFO，验证内部会话已建立、连接流程仍在继续、底栏保持灰色。释放响应后验证橙色及实际名称，再次刷新验证名称保持。
- `ui-final/connection-session-pending.png` 和 `ui-final/connection-ready-named.png` 为上述阶段截图。原生界面回归共 345 项通过。
- 独立后台 IPC 检查 651 项通过，验证前台点击后的等待状态不提前发布完成颜色，终态快照确认后显示实际设备名。其余设备按钮、布局和 IPC 回归继续运行。
- 固件／上位机统一构建 V0.11.8；配套固件仅同步版本，未烧写。本轮没有实板连接、音频录放或 COM8 串口验收。
