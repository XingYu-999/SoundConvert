# 托盘快捷控制与卡片菜单验收

> V0.12.5 已按用户截图精简说明并将设备名置顶，当前布局见[托盘菜单精简验收](49-托盘菜单精简验收.md)。以下记录保留 V0.12.4 的交付状态。

本批版本 **V0.12.4**，日期 2026-10-22。参考用户提供的 QQ 音乐托盘截图，将文字菜单改为白色卡片式弹出面板，并加入现有六个 Host 快捷控制。

## 使用与控制边界

右键通知区域的程序图标打开菜单，左键仍打开主窗口。顶部为上一曲、播放／暂停、下一曲，下方为 Host 音量减、静音键、音量加。设备名称和按键结果随现有前台状态更新；播放器实际状态未知，播放暂停图标不伪装成已播放或已暂停。

“电脑输出音量”滑块及旁边的静音按钮操作当前选择的电脑播放端点。静音以橙色图标和浅色背景持续显示。它们与 Host HID 音量键、主页的声卡内部音量分别对应不同控制路径，不通过滑块设置远端 Host 绝对音量。

菜单保留输出开关、打开主窗口、设备管理、播放输出、日志、设置和退出。Host 按键、输出开关及音量操作保留菜单打开，便于连续操作；按键请求未完成时忽略重叠点击，不排队、不自动重发，也不会让整排按钮短暂变灰。导航操作关闭菜单后打开对应主窗口页面。

点击菜单外导致失焦或按 Esc 关闭面板，Tab 焦点在面板内循环。通过 Alt+F4 等窗口关闭路径结束面板后，再次右键会重新创建并绑定同一模型。关闭面板不退出软件，主窗口收起到托盘后仍能操作。菜单只有一个“退出”，继续调用现有整应用退出路径，停止音频并回收所属后台；菜单本身不创建音频服务或第二套设备连接。

## 实现与显示器适配

`WindowsTrayIcon` 继续使用 Windows 通知图标、现有 ICO、状态提示与 Explorer 重建通知区域后的注册逻辑。右键事件读取真实图标矩形及所属显示器工作区，使用屏幕物理像素传递锚点；键盘触发／未提供坐标时也优先使用图标所属屏幕。

`TrayService` 延迟创建并复用一个 `TrayMenuWindow`，绑定同一 MainViewModel。无标题栏、不进入任务栏，失焦隐藏，服务释放时关闭。菜单宽度为 286 DIP，内容过高时限制在工作区内并提供滚动。初次窗口先在目标工作区内创建，再核对原生 DPI／客户区宽度和实际布局，最后放到锚点并显示，避免边缘创建时裁切或闪现。

菜单图标复用现有 Host 矢量与 Windows 图标字体。白底、灰色圆形按钮、灰色音量轨道和分隔线参考截图；额外的六键、设备／HID 状态及导航使菜单高度大于 QQ 示例。视觉对照和修正见根目录 `design-qa.md`。

## 实板与人工操作边界

本批未烧写／复位开发板、未操作 COM8、未录放真实音频。菜单中的命令路径使用真实 MainViewModel、独立 Engine 和本机 TCP 设备替身；失焦检查使用原生窗口消息，不等同于实际鼠标点击。需在真实 USB Host 上复核媒体键响应，以及实际托盘图标、溢出区域、鼠标点击／拖动和跨屏日常使用体验。

退出旧程序后运行新目录内 `client-win-x64/SoundConvertClient.exe`，保留完整 Engine 目录。此托盘功能使用完整新版客户端即可生效，无需为菜单外观更新刷写开发板。
