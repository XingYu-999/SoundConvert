# 双向音频与麦克风实施验收

日期：2026-10-19，Asia/Shanghai；交付 **V0.3.0**。按用户补充，本批只实现 **UAC1.0**，没有恢复已删除的UAC2。新功能是“电脑输入源→独立网络通路→开发板USB麦克风→USB Host”；原“USB Host播放→开发板→软件→耳机”保留。

## 十二项需求对应

| 要求 | 实现 |
| --- | --- |
| 1 常用格式 | 播放沿用十种双声道16/24-bit格式；录音新增单声道16-bit 8/16/32/44.1/48/96 kHz、24-bit 44.1/48/96 kHz，共9种。 |
| 2 输入源选择/检测 | 新“输入”页：刷新/选择设备、当前设备及采集格式、电平、3秒检测、发送音量/静音、独立启停；不保存录音，不在本机扬声器监听麦克风。 |
| 3 两方向最大规格 | 播放继续按PC输出设备格式与混音格式交集过滤；录音按PC输入源当前配置与采集格式交集过滤。录音可下混为mono、降采样/量化到较低选项，不能宣称高于源规格。 |
| 4 主页双向状态 | 分别显示电脑输出、开发板播放、电脑输入、开发板USB麦克风状态与实际/待启用格式。 |
| 5 独立设备图块 | IP、唯一ID、MAC、UAC1、USB声明版本2.0、握手Full-Speed/12 Mbit/s及固件；普通轮询不重复拉取静态身份。 |
| 6 详细监视 | 虚拟声卡页“开启监视”，默认关闭，5秒GET_STATS一次，忙时跳过，保留时间戳快照；控制/JSON处理中穿插优先播放服务。 |
| 7 端口 | 首页显示控制TCP49161；板播放UDP49162→PC49162；PC麦克风UDP49164→板49163。 |
| 8 独立通路 | WASAPI采集、独立麦克风发送线程/socket、板端socket5和SPSC队列、USB IN0x82；不复用播放UDP、接收线程或缓冲。停止麦克风不取消正在进行的共享TCP请求。 |
| 9 默认优先级 | PC发送线程BelowNormal、板端默认playback_first；可选同级，重新启用输入生效。播放接收保留原MMCSS/优先级。USB硬件中断不人为降级，Core0先服务播放再处理麦克风。 |

| 11 播放默认 | 出厂保存mask147，48/96 kHz×16/24-bit四项；已有保存偏好不覆盖。实际对Host开放集合仍受当前输出上限约束。 |

USB拓扑：AC接口0、播放AS1、录音AS2；OUT0x01、反馈IN0x81、麦克风IN0x82。IN不是原来的反馈端点。完整编译ELF模板1008 B，两个AS接口及所有格式/端点/FS总负载经过检查。麦克风每包独立采样索引，USB时钟与PC采集时钟由TinyUSB IN FIFO流控协调；不是强行每秒丢/补样本来维持水位。

## 使用与规格边界

1. 运行新软件，在“输入”页选择实际电脑麦克风，按“检测输入”检查采集帧/电平。显示收到静音与设备失败是不同状态。开发板自己的录音端点被排除，避免自反馈。
2. 在“虚拟声卡”页选择录音格式并保存；输入源超过当前上限的选项不可新启用。格式改变需USB重新枚举，会短暂停止两方向；切换同规格电脑输入源只重启麦克风通路。
3. 按“启用麦克风传输”。软件不会随启动自动采集；USB Host未打开录音时显示等待，Host打开后显示实际录音状态。发送增益/静音只改变发送样本，不改系统麦克风音量。
4. 开发板USB连接的Windows/其他Host把新设备作为麦克风使用。本次真实Host为当前Windows；NS2是否接受这个双向拓扑并用于游戏/聊天仍需实机验证。

最大规格指**当前Windows设备配置与采集/混音通路的上限**，不是猜测ADC/DAC物理极限。Windows混音显示float32/双声道不等于USB端正在使用该位深或声道；实际USB录音以capture.active、alternate_setting、format为准。普通GUI播放仍跟随共享输出格式；诊断96/24播放案例不能冒充当前耳机共享输出96 kHz。

反向麦克风本批使用PCM，无反向压缩/FEC；原播放仍可使用PCM/IMA与XOR4。真正缺失或超过重排期限的数据会显式统计并补零，不保证UDP绝不丢失。重排32槽、最多10 ms，连续数据立即交付；正常麦克风FIFO目标24 ms、物理容量16 KiB。未启用上游时按USB节拍发送静音，不能将容量或API请求值当总延迟。

## 实际联调发现和修复

- 普通WaitOne(1)受Windows定时粒度影响，初版发送速度不足并积压。改为进程内high-resolution waitable timer；不修改全局timer resolution或电源计划。
- 最初直接丢弃乱序包，把已经收到的音频误作缺失。增加按样本索引的有界重排；5 ms候选在120秒中仍有3包晚到，保留为失败，再利用已有24 ms麦克风缓冲把期限调为10 ms。
- 详细状态构造曾使原播放块超过4 ms期限，产生336源帧过期。控制/JSON分配和响应边界现在穿插播放服务；没有扩大原播放期限来掩盖问题。
- TinyUSB在任一AS切换后准备反馈，传入的alt可能来自麦克风。初版把麦克风alt1映射为48k，破坏96k播放反馈，实测出现大量USB欠载。现在反馈只依据已经提交的**当前播放采样率/位深**；有针对麦克风开关保持96k/3456 B目标的独立回归。
- 96 kHz播放时，一轮网络任务只读一包麦克风，收包速度不足。现在控制构造与各播放服务边界穿插有界收包，每次仅一包；默认先处理播放，原包等待≥2.5 ms或校验包等待≥3 ms时让出麦克风处理。播放期限仍为4 ms。
- 麦克风停止/故障不取消进行中的共享控制读写，避免连带关闭播放控制连接；输入格式草稿为空时先拒绝，不先停止声音。输入异常会停止自身采集/发送，保留播放。

所有候选失败、启动未等DHCP就绪的超时和修复后结果分文件保留，不用成功重试覆盖失败。

合成源通过真实USB IN在Windows采集，固定频率能量仅是数字链路判断，不是模拟音质、主观听感或物理延迟。实际麦克风源窗口不采用440 Hz指标。麦克风开启/关闭Host录音的窗口记录实际接口状态；主动切换的停止时段不作为连续有声数据承诺。停止/静音恢复、默认偏好和格式边界另有离线/原生界面检查。

## 开源开发依据

- [TinyUSB官方headset说明](https://docs.tinyusb.org/en/latest/examples/device/uac2_headset.html)：本地`examples/device/uac2_headset`包含FS UAC1的立体声播放和单声道麦克风。这里只借鉴UAC1拓扑；目录名含uac2不代表本项目恢复UAC2。
- `D:/GithubClone/tinyusb/src/class/audio/audio_device.c/.h`：IN FIFO流控、可设阈值、AS切换回调次序；ISR只计数，USB API留在Core0。阈值按格式设置而非使用巨大FIFO的一半作为固定延迟。
- `D:/GithubClone/screamrouter/src/audio_engine/receivers/system/wasapi_capture_receiver.*`：独立capture_loop、实际格式解析、分块分发。借鉴边界，没有移植其C++实现。
- `D:/GithubClone/roc-toolkit/src/internal_modules/roc_sndio/isource.h`：采集源与消费者时钟边界、reclock职责。这里保留PC原采集节奏，由USB IN流控协调消费。
- `D:/GithubClone/snapcast/server/streamreader/alsa_stream.*`：把采集设备封装为输入流，与消费/编码分离；不是直接将Linux ALSA代码放进Windows程序。

本批核心新代码自行实现，未把GPL/AGPL模块直接引入正常固件或软件依赖；TinyUSB继续遵守现有MIT声明。现有NAudio提供WASAPI采集，输入、输出使用不同对象与工作线程。
