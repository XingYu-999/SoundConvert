# V0.11.3 退出应用停止播放与后台回收验收

日期：2026-10-22。按用户本轮要求，禁止退出软件后继续播放。本批次由 V0.11.2 递增一次到 V0.11.3；固件仅同步版本，没有修改固件音频行为。

## 当前退出规则

- 托盘仅保留一个“退出”，设置页仅保留一个“退出应用”。两者和取消关闭到托盘后的窗口关闭使用同一退出流程。
- 正常退出先停止软件播放、麦克风回传、保活、控制连接和后台进程，再关闭界面。
- 后台无响应或清理失败时，取消前台代理任务，并回收本客户端启动且归属于本应用 Job 的后台，等待进程结束；记录异常清理日志，不能让 UI 退出后留着后台播放。
- UI 崩溃或只结束 UI PID 时，Windows Job 自动回收所属 Engine。Engine 在初始化 Runtime、音频端点和 IPC 之前加入所属 Job；无 owner 或 owner 已退出时拒绝独立启动。
- “收起到托盘”和最小化仍然保留 UI 进程，此时软件没有退出，可以继续播放。开启“关闭窗口时收起到托盘”时，点击窗口关闭按钮仍是收起；关闭该设置后，关闭按钮退出整个应用。
- 再次启动软件创建新的后台，按已保存的自动连接策略初始化。音频处理仍在独立 Engine 进程运行，不把 PCM、设备句柄或保活任务迁回 UI。

V0.10.0 至 V0.11.2 的“退出界面、后台继续”设计已被本规则取代。旧报告的真实通过／失败记录保留，不能当作当前退出行为的证据。README、设置说明、UI／时间同步规划及验收指南已同步更新；相关历史报告增加适用范围说明。

## 实现要点

`EngineLifetime` 创建不继承的唯一命名 Job，设置 `JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE`。Engine 启动时加入 Job 并立即释放临时打开的 Job 句柄，前台客户端持有其生命周期。机制参考 [Microsoft Job Objects 文档](https://learn.microsoft.com/en-us/windows/win32/procthread/job-objects)。父侧也跟踪自己启动的子进程，覆盖测试启动器，并在释放 Job 后确认进程结束。

`EngineClient.DisposeAsync()` 对本客户端启动的后台优先请求正常 shutdown（3 秒应答、10 秒进程退出预算），失败时停止代理重连并释放所属 Job。MainViewModel 的退出清理也会先请求停止已验证的现有后台。附加到其他活跃所有者的低层只读客户端仅断开自身 IPC，不能因检查客户端的 Dispose 杀掉其他前台的后台；强制回收仅作用于自己启动的 Job。原管道 PID、路径、启动时间、会话、版本和 InstanceId 验证保留。

`ShutdownEngineCommand`／`ShutdownAndExitAsync` 保留为兼容别名，统一转向相同退出清理路径，不再提供第二种用户退出语义。

本轮未刷写固件、未执行 COM8 115200/8N1 联调、未执行真实耳机／Host 的播放停止或双向音频验收。真实进程回收可证明没有残留的本应用 Engine，不能把它写成耳机物理听音验收。前批 HID 上下曲真实 Host 复验仍待完成。

## 后续音频验证约定

当前 `ProductionDuplexChecks` 持续音频矩阵改为 `attached,control,final`，UI 保持运行，结束时正常停止 Engine。旧 `detached`／`crash` 连续播放矩阵在设备操作前拒绝；退出／崩溃停止要求由独立生命周期检查验证。时钟短测及长测的新客户端配置同步采用 UI 存活阶段；冻结的旧客户端兼容对照仍按其历史工具解释。此次只编译／离线检查这些工具（时钟采证自检 39 项通过），没有重新进行实板短测或长测；EngineUiChecks 的可选实板分支也改为隐藏／显示同一窗口，不再销毁 UI 后要求音频继续。

## 使用新版

先用旧版“停止后台并退出”结束旧前台和后台，再启动 `artifacts/releases/V0.11.3/client-win-x64/SoundConvertClient.exe`，保留完整 Engine 子目录。当前版本不会强制终止版本／身份不匹配的旧后台。配套固件在 `firmware` 目录，仅构建交付，尚未刷写。
