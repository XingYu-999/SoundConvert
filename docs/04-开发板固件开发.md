# 开发板固件开发

适用基线：2026-10-22，VERSION 0.12.12。返回 [文档导航](../README.md)。固件目录是 `SoundConvertBoard/`，主要 C 文件直接位于目录根部，USB 模块在 `usb/`，不要按不存在的 `src/`、`include/` 路径寻找。

## 1. 启动流程和基础约束

[SoundConvertBoard.c](../../SoundConvertBoard/SoundConvertBoard.c) 的 `main()` 依次初始化 UART、加载启动配置并开始 USB、初始化 LD2、准备网络配置、设置安全 Flash 与看门狗，再启动 Core 1。Core 0 主循环执行 USB、指示灯和看门狗任务。Core 1 使用普通 SRAM 中的独立 16 KiB 栈，承载 JSON 和事务处理。

USB 上电自运行不等待 DHCP 或管理客户端。手动 STOP 后，网络重连不能重新 START；只有显式命令或整机重新上电改变该运行意图。

平台使用 Pico SDK 2.3.1、C11／C++17、RP2350 Arm-S 和 2 MiB Flash。编译入口及源文件清单见 [CMakeLists.txt](../../SoundConvertBoard/CMakeLists.txt)。链接 `hardware_dma` 不表示现有 SPI 音频收发已经采用 DMA。

## 3. USB 开发不能越过的边界

TinyUSB API 仅由 Core 0 调用。Core 1 请求启停和运行增益时使用现有邮箱，不能直接执行 `tud_*`。名称／描述符配置使用专用接口，在实际 STOPPED 且没有待执行 START 时验证并更新，随后由 Core 0 负责重新连接和枚举；不能把这些配置接口误当作任意状态均可调用的 TinyUSB 接口。USB 回调中不访问 SPI／TCP，不写 Flash，不动态分配，不格式化大量日志。

当前接口通常为 AC 0、播放 AS 1、麦克风 AS 2；实际是否存在录音接口取决于 profile。端点包括播放 OUT `0x01`、反馈 IN `0x81`、录音 IN `0x82`、HID IN `0x83`。正式 HID 报告为两字节有限位图，无 Report ID；释放为全零。实验 UAC1 状态通知端点不属于默认正式配置。

USB owner 状态为 STOPPED、STARTING、RUNNING、STOPPING、FAULT。命令 accepted 不等于已经达到 STOPPED；描述符写入和 Flash 保存必须等待实际停止，并核对 `emulation_revision`。

播放 FU2 只提供 master mute／volume，L/R 控制位为零；范围 −60～0 dB，Q8.8，步长 1/256 dB。增益只对每个声道应用一次。独立内部增益为 0–100% 幅值，默认 80%，Host 改 FU 不覆盖它。录音 FU7 与这两者独立，网络录音增益可被 Host 改写。

### 修改格式或描述符

1. 同时修改 `usb_formats.h`／麦克风格式定义、描述符生成器、USB 请求校验和 PC 端 `AudioFormat`／`CaptureFormat`。
2. 保留已有 mask 的 bit 顺序，新增合法组合，不能从采样率与位深列表任意组合。
3. 核算 Full-Speed 每帧包长、FIFO、块结构、网络载荷、FEC 和内存上限。
4. 测试所有 profile、格式子集、alt0、复位、挂起和停止／恢复。
5. 用实板 Host 读取实际描述符和格式，不以 WASAPI 接受某个上层格式替代 USB 格式证据。

## 4. 双核音频队列

播放由 Core 0 发布完整 `usb_audio_block_t`，包含 PCM、帧数、采样率、格式、generation、sample_index 和提取时间。队列使用 release／acquire 保证数据在索引发布前完整写入；Core 1 复制完成才释放槽。不能仅给 64 位字段加 `volatile` 就认为跨核快照安全。

Core 1 读取播放块时会丢弃旧代次或超过 4 ms 的块，不能为了“少丢包”无限发送陈旧声音。USB 短块、reset 或未知时间轴损失需更新 generation，不能伪造连续样本索引。单包发送暂忙应保留原字节和序号，真正过期才记录丢弃。

录音方向由 Core 1 校验 UABM、执行有限重排，再交给 Core 0。缺口补零、晚包、过期和 FIFO 欠载分别计数。扩大 FIFO 物理容量不应隐式提高正常目标积压。

## 5. W5500 网络资源

现有代码使用 SPI0，初始化频率 25 MHz，实际值通过统计读回。当前源码引脚为：

| 功能 | GPIO |
| --- | ---: |
| MISO／CS／SCK／MOSI | 16／17／18／19 |
| W5500 RESET／INT | 20／21 |
| LD2 PWM | 25 |

这是当前板型代码映射，移植前仍需核对原理图。INT 引脚存在不代表所有业务都由中断驱动。

| 硬件 socket | 用途 | TX／RX，KiB |
| --- | --- | --- |
| 0 | MACRAW：仅 ARP 地址冲突探测 | 2／2 |
| 1 | 播放 UDP，复用可选 UABT | 4／2 |
| 2 | TCP 控制槽 1 | 2／2 |
| 3 | DHCP | 1／1 |
| 4 | UDP 发现 | 1／1 |
| 5 | 反向麦克风 UDP | 2／4 |
| 6 | TCP 控制槽 2 | 2／2 |
| 7 | NetBIOS 名称查询 | 2／2 |

TX 与 RX 各分配 16 KiB，8 个 socket 均已有职责。增加功能优先考虑既有 socket 的有界复用，不能假定存在空闲 socket。板端自动端口仅改变 socket 的 UDP 端口号，不增加 socket。

主循环在地址、发现、两路控制和事件处理之间反复服务音频；大控制 JSON 内也有服务机会。修改代码时检查最长连续执行段，不能只看一轮总耗时。同步 SPI 短 burst、底层命令轮询仍存在，当前没有硬实时最坏完成保证。

### 增加网络命令

1. 在能力应答中明确新功能和版本；旧客户端未请求时保持原有行为。
2. 在 `uab_network.c` 校验 owner、boot、请求序号、参数类型、值域和前置状态。
3. 决定它是只读、运行控制还是持久事务，正确选择去重／结果缓存策略。
4. USB 行为经邮箱交给 Core 0，返回“已受理”并通过快照说明最终状态。
5. 将大块处理拆成有预算的阶段，维护诊断计数，不添加逐包 UART 打印。
6. 同步 PC 客户端、协议文档和异常向量，再做真实 Host 验证。

## 6. Flash 配置如何扩展

末尾 `0x101FE000`–`0x101FFFFF` 共 8 KiB 分为两个 4 KiB 槽。固件链接区和 UF2 验证都保护该区域；普通更新不能整片擦除。

当前记录版本为 v8，有效载荷 796 字节，兼容读取 v1–v7。v8 新增 LD2 模式字段，旧记录默认自动。记录包括 CRC 与独立提交页，写新槽失败仍保留旧有效槽；不要把 `uab_config_t` 内存布局直接写入 Flash。

新增持久字段时：

1. 在结构和默认值中定义合法范围；区分未出现、未知枚举和明确用户输入。
2. 修改显式编码／解码并递增记录版本，保留旧格式长度与迁移逻辑。
3. 修改 GET_CONFIG、candidate 校验、CONFIRM 后应用及客户端草稿。
4. 验证中断擦除／数据写入／提交页、CRC 损坏、最新槽损坏回退和旧记录迁移。
5. 用真实板卡验证升级保留配置；降级单独检查旧固件能否读取新记录。

不能把内部音量、流 token 或电脑端口策略顺手写进 Flash。只有明确保存持久配置才走事务并落盘。

## 7. 灯效与时间侧带

LD2 支持 auto／off／on／breathe／blink，由 Core 0 每次做有界更新。auto 以 USB 枚举和新音频数据判断，不以 TCP 已连接或样本非零判断；数字静音仍算音频流。IDENTIFY 临时覆盖所选模式，结束恢复，不写 Flash。

UABT 是可关闭的软件观测侧带，复用播放 socket。处理预算为 100 μs，超过预算会撤销观测并锁存失败身份；健康音频继续。不能通过同身份反复 enable 或 RESET_STATS 清锁；不能把协议中的软件采点写成 PHY／USB 硬件时间戳。

## 8. 依赖、检查和维护方法

依赖固定来源见 [DEPENDENCIES.md](../../SoundConvertBoard/vendor/DEPENDENCIES.md)：TinyUSB 固定提交附只读反馈诊断补丁，WIZnet ioLibrary 带非阻塞 recv 修正，cJSON 带精确数字序列化修正。更新依赖前应逐个审查这些修改，不能直接替换为最新分支。

宿主测试位于 `tests/`，通过 [Run-HostChecks.ps1](../../SoundConvertBoard/tests/Run-HostChecks.ps1) 编译生产模块加平台替身，覆盖 USB、配置、封包、发送、DHCP、时钟、端口、灯效等。它们验证逻辑和边界，不证明 USB IRQ、实板跨核时序、Flash 断电或真实网络压力。

定位问题时按 USB 收到 → 队列 → 发送提交 → SENDOK → PC 接收 → 输出逐段取证。`audio_packets_sent` 是提交计数，`audio_send_completions` 是硬件发送完成，均不是耳机播放确认；`RESET_STATS` 的网络运行计数与 boot 内 USB 计数口径也不同。

详细命令和证据记录要求见 [构建测试与发布](05-构建测试与发布.md)。
